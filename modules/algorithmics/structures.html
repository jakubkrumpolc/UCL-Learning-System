Lists, arrays, linked lists, stacks and queues

A data structure organises data for an algorithm. Choosing it is a key decision even in small programs: a poor choice can force a worse algorithm.

Remember: Stack: last in, first out (a pile of plates). Queue: first in, first out (a bus queue).

More detail

The notes describe a queue as “like stacks but items are added at one end and removed from the other end”: the item that has waited longest leaves first.

In Python a list works as a stack (append to push, pop() to pop); for a queue use collections.deque with append and popleft.

Part 2 · Structure

Graphs: nodes and arcs

A graph G is a pair (N, A): a set of nodes N (vertices) and a set of arcs A (edges, links), with A ⊆ N × N. Each arc (x, y) is an ordered pair, drawn as an arrow x → y.

N = {a, b, c, d}, A = {(a, b), (b, a), (b, c)}. Node d has no arcs.

Directed and undirected

By default a graph is directed. It is undirected if (x, y) ∈ A exactly when (y, x) ∈ A: then each pair is drawn as one line without arrows.

Weighted

A weighted graph has a value on each arc: cost, length, benefit, capacity…

Remember: A graph is nodes plus arcs. Arrows mean directed; plain lines mean both directions; numbers on arcs are weights.

More detail

Graphs model road maps (weights = distances), networks (capacities), dependencies between tasks, and much more. Most of the algorithms in Parts 3, 5 and 6 work on graphs.

A graph can be stored as an adjacency matrix L, where L[i, j] is the weight of arc (i, j) (∞ or 0 if there is none), as Prim's, Dijkstra's and Floyd's algorithms do, or as an adjacency list per node.

Source: Algorithms and Data Structures notes, section 3, pages 49–51.

Part 2 · Structure

Paths, subgraphs and connected graphs

Path

A path is a sequence of arcs joined end to end from one node to another, respecting their direction.

Subgraph

H = (M, B) is a subgraph of G = (N, A) if M ⊆ N and B ⊆ {(x, y) ∈ A | x, y ∈ M}: some of the nodes, and some of the arcs between them.

Connected

Undirected: connected if every pair of nodes is joined by a path. Here {a, b, c, d} and {e, f} are each connected.

Strongly connected

Directed: strongly connected if there's a path from every node to every other. {a, b, c, d} is; {e, f} isn't (no way back from f).

Acyclic

A DAG: directed, with no cycles (no node has a path back to itself).

Remember: Connected: one piece (undirected). Strongly connected: you can get from anywhere to anywhere following the arrows.

More detail

“Connected” is for undirected graphs and “strongly connected” for directed ones, where a path must follow the arrows.

DAGs model things like prerequisites (a module before another) and task schedules: there's no circular dependency.

Source: Algorithms and Data Structures notes, section 3, pages 52–56.

Trees, binary trees and complete binary trees

Root A (purple); leaves H, I, J, F, G (orange). Height 3.

Words to know

  • A graph is a tree if there's a node r, the root, from which every other node can be reached by a unique path
  • If x has an arc to y below it, y is a child of x and x is its parent
  • Leaves are the nodes with only one arc (no children)
  • A branch is a path from the root to a leaf
  • Height = number of arcs on the longest branch

Binary tree

A binary tree has at most two children per node.

Complete binary tree

A complete binary tree has every layer full except perhaps the last, which is filled from left to right. At most one non-leaf node has one child; each full layer has twice as many nodes as the one above.

Remember: Tree: one root, a unique path to every node. Height counts arcs, not nodes, on the longest branch.

More detail

The tree above is in fact a complete binary tree: the first three layers are full, and the last layer (H, I, J) is filled from the left with no gaps. It has exactly the shape of the 10-item heap below. Remove I and it would no longer be complete.

A complete binary tree with n nodes has height ⌊log₂ n⌋, which is why heap operations are fast (see Problem sheet 1, question 3).

Source: Algorithms and Data Structures notes, section 3, pages 57–59.

Part 2 · Structure

Tree traversal: preorder, inorder, postorder

Three ways to visit every node

OrderRuleVisits
Preordernode, then left subtree, then right subtreeA, B, D, H, I, E, J, C, F, G
Inorderleft subtree, then node, then right subtreeH, D, I, B, J, E, A, F, C, G
Postorderleft subtree, then right subtree, then nodeH, I, D, J, E, B, F, G, C, A

Remember: Pre, in, post = where the node goes: before, between or after its two subtrees.

More detail

Traversal means systematically visiting every node: it's a form of searching.

Each rule is recursive: “visit the left subtree” means apply the same traversal to that whole subtree. For inorder, start at A, go left to B, left to D, left to H: H has no children, so visit H, then D, then D's right subtree I, then back up to B, and so on.

A quick check: preorder always starts with the root, postorder always ends with it.

Source: Algorithms and Data Structures notes, section 3, pages 60–61.

Positions count from 1. The children of 14 (position 2) are at 4 and 5: 8 and 7.

Remember: Heap in an array: children of position i live at 2i and 2i + 1, so no pointers are needed.

More detail

Because a heap is a complete binary tree, there are no gaps in the array: reading the tree layer by layer, left to right, gives the array.

The example is a max-heap: every parent is at least as big as its children, so the largest value sits at the root. (The notes define the shape; the ordering is what makes heaps useful for priority queues and HeapSort.)

Source: Algorithms and Data Structures notes, section 3, pages 62–63.
