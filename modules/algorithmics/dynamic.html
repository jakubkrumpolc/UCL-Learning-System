Dynamic programming

Solve each subproblem once, store the answer, and build up from the smallest: binomial coefficients and shortest paths between every pair of nodes.

Part 5 · Dynamic

Dynamic programming

For optimisation problems where the same subproblems come up again and again: store each subproblem's solution the first time, and reuse it. This can turn exponential time into polynomial time.

Divide and conquerDynamic programmingGreedy
Directiontop-down: split the problembottom-up: start with the smallest subinstancesone step at a time
Subproblemsindependentoverlapping: they share sub-subproblems—
Choice—global: compares the combinationslocal: best-looking step now
Repeated workyes, if subproblems overlapnone: each solved oncenone

Remember: Dynamic programming = remember the answers to overlapping subproblems and build upwards from the smallest.

More detail

Divide and conquer on overlapping subproblems does more work than necessary because it solves the same subproblem repeatedly, as recursive Fibonacci does. Dynamic programming solves each one once.

Like greedy algorithms, dynamic programming applies to optimisation problems where a series of choices leads to an optimal solution. The difference: greedy commits to the locally best choice, dynamic programming keeps the information needed to make the globally best one.

Source: Algorithms and Data Structures notes, section 6, pages 127–130.

Optimal substructure

Has it

Shortest route

Manchester

Birmingham

London

If Birmingham is on the shortest route from Manchester to London, then that route is the shortest Manchester → Birmingham plus the shortest Birmingham → London.

Doesn't have it

Fastest route (with fuel)

Manchester

Birmingham

London

The fastest Manchester → Birmingham drive may burn so much fuel that you need a fuel stop before London. Going slower on the first leg can make the whole journey faster.

Remember: Optimal substructure: an optimal solution is made of optimal solutions to its subproblems. Dynamic programming needs it.

More detail

When a problem lacks optimal substructure, combining the best answers to the pieces doesn't give the best answer to the whole, so storing and reusing them doesn't help.

Floyd's algorithm relies on exactly the shortest-route property: if j is on a shortest path from i to k, the shortest paths i → j and j → k together make a shortest path i → k.

Source: Algorithms and Data Structures notes, section 6, pages 131–132.

Binomial coefficients: Pascal's triangle

C(n, k), “n choose k”, is the number of ways of picking k items from n: n! / ((n − k)! k!).

BC(n, k)
  if k = 0 or k = n then return 1
  else return BC(n − 1, k − 1) + BC(n − 1, k)

The recursive version recalculates the same values many times.

Dynamic programming: store the values in a table instead. Each entry is the sum of the two above it. Time in the order of nk.

The table, row by row

Remember: C(n, k) = C(n − 1, k − 1) + C(n − 1, k): fill Pascal's triangle row by row instead of recursing.

More detail

Each row only needs the row above, so one array of size k is enough: update it from right to left (so you don't overwrite a value you still need) n times. That's n × k additions.

Example: C(8, 4) = 70 = C(7, 3) + C(7, 4) = 35 + 35.

Source: Algorithms and Data Structures notes, section 6, pages 133–137.

Floyd's algorithm: shortest paths between every pair

Floyd(L[1..n, 1..n])
  D = L
  for k = 1 to n do
    for i = 1 to n do
      for j = 1 to n do
        D[i, j] = min(D[i, j], D[i, k] + D[k, j])
  return D

Input L = D₀ (∞: no arc)

a1a2a3a4a5
a103∞4∞
a2∞0421
a3∞∞0∞∞
a44∞∞03
a5∞∞220

Output D₅: every shortest path

a1a2a3a4a5
a103644
a260321
a3∞∞0∞∞
a447503
a569220

Remember: Floyd: for each node k in turn, ask every pair “is it shorter to go via k?”. Three nested loops: n³.

More detail

Compare Dijkstra: shortest paths from one node. Floyd gives the shortest path cost between every pair.

The input is an adjacency matrix with L[i, i] = 0, L[i, j] = the weight of arc (i, j), and ∞ where there's no arc. After k rounds, D[i, j] is the shortest path from i to j using only nodes 1..k as intermediate stops; after n rounds every node is allowed, so D holds the true shortest paths.

Row a3 stays ∞ (except the diagonal) because a3 has no outgoing arcs: nothing can be reached from it.

The order in which intermediate nodes are tried doesn't matter for the final answer, as the notes show with a second example.

Source: Algorithms and Data Structures notes, section 6, pages 138–142, 148–149.

FloydPath: recovering the route

FloydPath(L[1..n, 1..n])
  D = L
  set P to 0
  for k = 1 to n do
    for i = 1 to n do
      for j = 1 to n do
        if D[i, k] + D[k, j] < D[i, j] then
          D[i, j] = D[i, k] + D[k, j]
          P[i, j] = k
  return D and P

P[i, j] records an intermediate node on the best route. 0 means: a direct arc, no path, or i = j.

P for the example

a1a2a3a4a5
a100502
a240500
a300000
a401500
a544000

Tracing a route back

a1 → a3: P[1, 3] = 5, so go via a5. P[1, 5] = 2: via a2. P[1, 2], P[2, 5], P[5, 3] are 0: direct. Route a1 → a2 → a5 → a3, cost 6.

a5 → a2: P[5, 2] = 4: via a4. P[4, 2] = 1: via a1. Route a5 → a4 → a1 → a2, cost 9.

Remember: Floyd gives the cost; FloydPath also stores a stop P[i, j] on each route, and you rebuild the route by splitting at that stop, recursively.

More detail

To rebuild the path from i to j: if P[i, j] = 0 the route is the direct arc; otherwise it's the path from i to P[i, j] followed by the path from P[i, j] to j, each rebuilt the same way.

This is the same P matrix as the notes' “Deconstructing a P matrix” example.

Source: Algorithms and Data Structures notes, section 6, pages 150–153.

Warshall's algorithm: is there a path at all?

Warshall(L[1..n, 1..n])
  D = L
  for j = 1 to n do
    for i = 1 to n do
      if i ≠ j and D[i, j] = true then
        for k = 1 to n do
          D[i, k] = D[i, k] or D[j, k]
  return D

Floyd with true/false

  • Input: a Boolean adjacency matrix, L[i, j] = 1 if there's an arc i → j, else 0
  • Output: D[i, j] = 1 if there's a path from i to j
  • The result is the transitive closure of the graph
  • If i can reach j, then i can reach everything j can: OR j's row into i's row

Remember: Warshall answers “can I get there at all?” instead of “how far?”: Floyd with or in place of min and +.

More detail

In the Floyd example graph, every node can reach every other except a3, which has no outgoing arcs: its row stays all 0.

Like Floyd, Warshall takes time in the order of n³ for n nodes.

Source: Algorithms and Data Structures notes, section 6, pages 154–155.
