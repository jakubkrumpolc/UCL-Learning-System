Graph search: depth-first and breadth-first

Two systematic ways to visit every node of a graph: dive deep with a stack, or spread out level by level with a queue.

Sections 36–39 · Notes, section 7

Part 6 covers section 7 of the notes, “Graph search algorithms”: depth-first search (recursively and with an explicit stack) and breadth-first search (with a queue), each producing a spanning tree of the graph.

Visiting every node: two strategies

Two ways round

Depth-firstBreadth-first
Strategygo as deep as possible, then back upvisit all neighbours, then theirs
Data structurestack (or recursion)queue
Order from node 11, 2, 3, 6, 5, 4, 7, 81, 2, 3, 4, 5, 6, 7, 8

Both visit every node, and both produce a spanning tree: all the graph's nodes and a subset of its arcs.

Remember: Depth-first dives down a path before trying alternatives; breadth-first sweeps outwards in rings.

More detail

Neighbours are taken in increasing order (1, 2, 3, …), as in the notes. A different order gives a different, equally valid, traversal and tree.

The graph is undirected: edges 1–2, 1–3, 1–4, 2–3, 2–5, 3–6, 5–6, 4–7, 4–8, 7–8.

Source: Algorithms and Data Structures notes, section 7, page 157.

Depth-first search

Search(G)
  for each v ∈ N do mark[v] = notVisited
  for each v ∈ N do
    if mark[v] ≠ visited then DepthFirstSearch(v)
DepthFirstSearch(v)
  mark[v] = visited
  for each node w adjacent to v do
    if mark[w] ≠ visited then DepthFirstSearch(w)
CallWhy
DFS(1)initial call
DFS(2)first unvisited neighbour of 1
DFS(3)neighbour of 2
DFS(6)neighbour of 3
DFS(5)neighbour of 6; no unvisited neighbours, back up
DFS(4)back at 1: its next unvisited neighbour
DFS(7)neighbour of 4
DFS(8)neighbour of 7; done

Depth-first tree

Purple: the depth-first search tree. Dashed: edges to nodes already visited.

Remember: DFS: visit, then immediately recurse into the first unvisited neighbour; back up only when stuck.

More detail

Search makes sure every node is reached even if the graph isn't connected: if unvisited nodes remain after a call, it starts again from one of them, giving a forest of trees.

The notes also run DFS on a directed version of the graph. There, following the arrows from 1 reaches 2, 3, 4, 8 and 7, but node 5 can't be reached, so Search starts a new tree at 5, which then visits 6.

Source: Algorithms and Data Structures notes, section 7, pages 158–165.

Depth-first search with a stack

DepthFirstSearch2(v)
  P = emptyStack
  mark[v] = visited
  push v on P
  while P is not empty do
    while there is a node w adjacent to top(P)
          with mark[w] ≠ visited do
      mark[w] = visited
      push w on P
    pop top(P)

The same search without recursion: the stack remembers the path back.

Remember: Recursive DFS uses the call stack; the iterative version uses its own stack. Push to go deeper, pop to back up.

More detail

top(P) reads the top of the stack without removing it. A node is popped only once it has no unvisited neighbours left.

This formulation makes the comparison with breadth-first search clear: the only real difference is a stack instead of a queue.

Source: Algorithms and Data Structures notes, section 7, pages 166–169.

Breadth-first search with a queue

BreadthFirstSearch(v)
  Q = emptyQueue
  mark[v] = visited
  enqueue v into Q
  while Q is not empty do
    u = first(Q)
    dequeue u from Q
    for each node w adjacent to u do
      if mark[w] ≠ visited then
        mark[w] = visited
        enqueue w into Q
OperationQueue (front first)
enqueue 1; dequeue 1empty
enqueue 2, 3, 42, 3, 4
dequeue 2; enqueue 53, 4, 5
dequeue 3; enqueue 64, 5, 6
dequeue 4; enqueue 7, 85, 6, 7, 8
dequeue 5, 6, 7, 8empty

Breadth-first tree

Purple: the breadth-first tree. Every node hangs as close to the root as possible.

Remember: BFS: take the node at the front of the queue, add all its unvisited neighbours to the back. Nearest first.

More detail

A node is marked as visited when it's enqueued, not when it's dequeued, so it can't be added twice.

Because nodes are reached in order of distance (in edges) from the start, BFS finds shortest paths in an unweighted graph. For weighted graphs, use Dijkstra.

As with DFS, a Search3(G) wrapper restarts BFS from any node still unvisited.

Source: Algorithms and Data Structures notes, section 7, pages 170–174.
