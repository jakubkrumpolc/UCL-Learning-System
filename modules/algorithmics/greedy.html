Part 3 · Greedy

The greedy approach

The idea

  • Often simple, and often used for optimisation problems
  • The solution is built incrementally: at each stage the next part is added
  • No backtracking: a choice is never undone
  • A locally optimal strategy: best-looking step now
  • Not guaranteed to succeed on every problem, but provably optimal on some (e.g. shortest paths in a graph)

Example: customer queues

Customers each need one task done (cars at a garage, print jobs). Each one's waiting time includes all the tasks served before. Minimise the average wait.

Greedy: serve the shortest task first, then the next shortest, and so on.

Remember: Greedy: take the best-looking step now and never look back. Fast and simple, but only sometimes optimal.

More detail

Shortest-task-first is optimal for the queue problem when all the tasks are available at the start: any order that serves a longer task before a shorter one can be improved by swapping them.

The example task times are illustrative. Of the six possible orders, serving 3, then 5, then 10 gives the smallest total (29), so the smallest average wait (about 9.7).

Giving change

Greedy strategy

Largest coin first

To give change for X, use the largest coin Y that fits, then give change for X − Y the same way.

With coins 1, 2, 5, 10, 20, 50, greedy always uses the fewest coins: 68 = 50 + 10 + 5 + 2 + 1.

When it fails

With coins 10, 9, 1 and change of 27:

StrategyCoinsCount
Greedy10, 10, 1, 1, 1, 1, 1, 1, 19
Best9, 9, 93

Taking the first 10 looked best but ruled out the optimal answer.

Remember: Largest coin first is optimal for normal coin sets, not for every set: 27 from {10, 9, 1} breaks it.

More detail

Whether greedy works depends on the problem's structure, here on the coin values. Dynamic programming (Part 5) solves change-making optimally for any coin set by considering every amount up to X.

Source: Algorithms and Data Structures notes, section 4, page 68.

Minimum spanning trees

The problem

G = (N, A) is a connected undirected graph with a non-negative length (cost) on each edge.

Find a subset T of the edges that keeps all nodes connected with the smallest total length. (N, T) is a minimum spanning tree.

Think: the cheapest network of cables that links every building.

Tiny example

A triangle has 3 spanning trees (drop any one edge). With lengths 1 < 2 < 3, keep the two shortest: total 3.

Remember: A spanning tree connects all n nodes with exactly n − 1 edges and no cycle; the minimum one has the smallest total.

More detail

Any spanning tree of n nodes has exactly n − 1 edges: fewer can't connect everything, more would create a cycle.

In the notes' version, the edges are labelled x, y, z with x < y < z, and the tree with x and y is the minimum.

Source: Algorithms and Data Structures notes, section 4, pages 69–70.

Part 3 · Greedy

Kruskal's algorithm

Total length 1 + 2 + 3 + 3 + 4 + 4 = 17.

Kruskal(N, A, Cost)
  sort A by increasing cost
  T = ∅
  n = |N|
  repeat
    (u, v) = shortest edge not yet considered
    ucomp = Find(u)
    vcomp = Find(v)
    if ucomp ≠ vcomp then
      Merge(ucomp, vcomp)
      T = T ∪ {(u, v)}
  until |T| = n − 1
  return T

Find(x) gives the component containing x; Merge joins two components.

Remember: Kruskal: take the cheapest edge anywhere that doesn't make a cycle; stop at n − 1 edges. A forest that merges into one tree.

More detail

Kruskal grows several trees at once (the components) and merges them. An edge whose two ends are already in the same component would close a cycle, so it's rejected, as (a2, a5) is at step 6.

Sorting the edges dominates the running time: about a log a for a edges.

Source: Algorithms and Data Structures notes, section 4, pages 71–75.

Prim's algorithm

Started from a3 (purple). Total again 17, but a different tree.

Prim(N, A, Cost)
  T = ∅
  B = {x}    (x: any node)
  while B ≠ N do
    find (u, v) of minimum cost
      such that u ∈ N − B and v ∈ B
    T = T ∪ {(u, v)}
    B = B ∪ {u}
  return T
StepEdgeB (the tree so far)
start{a3}
1(a2, a3) 2{a2, a3}
2(a1, a2) 1{a1, a2, a3}
3(a2, a5) 4{a1, a2, a3, a5}
4(a4, a5) 3{a1, a2, a3, a4, a5}
5(a4, a7) 4… a7
6(a6, a7) 3all seven

Remember: Prim: grow one tree from a start node, always adding the cheapest edge from the tree to a node outside it.

More detail

At step 3 there's a tie: (a1, a4) and (a2, a5) both cost 4. Either may be chosen, so the minimum spanning tree is not unique, though its total is.

The detailed version keeps two arrays for every node i outside the tree: Nearest[i], the tree node closest to i, and MinDist[i], the distance to it (−1 once i is in the tree). Each round picks the node with the smallest MinDist, adds it, then updates the arrays using the new node's row of the cost matrix L, where L[i, j] = ∞ if there's no edge. Before the first round, starting from a3: MinDist[a2] = 2, MinDist[a5] = 5, MinDist[a6] = 6, and ∞ for a1, a4, a7.

Prim(L[1..n, 1..n])
  T = ∅
  for i = 2 to n do
    Nearest[i] = 1
    MinDist[i] = L[i, 1]
  repeat n − 1 times
    min = ∞
    for j = 2 to n do
      if 0 ≤ MinDist[j] < min then
        min = MinDist[j]; k = j
    T = T ∪ {(k, Nearest[k])}
    MinDist[k] = −1
    for j = 2 to n do
      if L[k, j] < MinDist[j] then
        MinDist[j] = L[k, j]; Nearest[j] = k
  return T

Kruskal builds a forest that merges; Prim always has exactly one tree. Both are greedy and both are optimal.

Source: Algorithms and Data Structures notes, section 4, pages 76–84.

Dijkstra's algorithm: shortest paths from one node

Purple: the shortest paths from a1 that the algorithm finds.

Dijkstra(L[1..n, 1..n])
  C = {2, 3, .., n}
  for i = 2 to n do
    D[i] = L[1, i]
  repeat n − 2 times
    v = element of C minimising D[v]
    C = C − {v}
    for each w ∈ C do
      D[w] = min(D[w], D[v] + L[v, w])
  return D
StepvCD = [a2, a3, a4, a5]
start{a2, a3, a4, a5}[50, 30, 100, 10]
1a5{a2, a3, a4}[50, 30, 20, 10]
2a4{a2, a3}[40, 30, 20, 10]
3a3{a2}[35, 30, 20, 10]

Remember: Dijkstra: repeatedly settle the closest unsettled node, then check whether going through it shortens the others.

More detail

Input: a weighted directed graph and a designated source node (row and column 1 of the matrix L). Output: the cost of the shortest path from the source to every other node.

S is the set of settled nodes (all nodes not in C). A path is special if all its intermediate nodes are in S. D[i] holds the cost of the shortest special path to i; when a new node v joins S, a path through v may be shorter, hence D[w] = min(D[w], D[v] + L[v, w]).

Final costs: a2 35 (via a3), a3 30, a4 20 (via a5), a5 10. The loop runs n − 2 times because once only one node is left in C, its distance can't improve.

Dijkstra needs non-negative weights. The simple array version takes time in the order of n².

Source: Algorithms and Data Structures notes, section 4, pages 85–92.

Where greedy fails: the travelling salesperson

The problem

Visit every city once and return home, as cheaply as possible.

Greedy rule: take the shortest edge available, such that it (1) doesn't close a cycle early (only the very last edge may), and (2) isn't a third edge at any city (each city has one way in, one way out).

In the notes' six-city example, greedy finds a route costing 58, but a cheaper one costs 56.

A small example

EdgesCost
GreedyAB 1, CD 2, AC 3, then BD 1016
BestAB 1, BC 4, CD 2, DA 411

Remember: Prim, Kruskal and Dijkstra are greedy and optimal; for the travelling salesperson, cheap early choices can force an expensive last edge.

More detail

The four-city example above is our own illustration (the six-city graph from the lecture is in the slides). After AB, CD and AC, cities B and D each have one edge left to fill, so the tour must close with BD = 10.

No efficient algorithm is known that always finds the optimal tour: checking all routes takes time that grows factorially with the number of cities. Greedy gives a quick, usually decent, answer instead.

Source: Algorithms and Data Structures notes, section 4, pages 93–97.
