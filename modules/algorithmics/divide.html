Part 4 · Divide

Divide and conquer

Divide: split the problem into smaller subproblems

Conquer: solve each one (often recursively)

Combine: put their solutions together

Three requirements

  1. A way of splitting the problem
  2. A way to solve small instances directly
  3. A way to recombine the small solutions into the whole solution

Not everything recursive is divide and conquer

Recursive Fibonacci looks similar but doesn't qualify: Fibonacci(n − 1) and Fibonacci(n − 2) aren't smaller independent pieces of the problem; they overlap heavily, so the same work is repeated.

Remember: Divide, conquer, combine. It pays off when the pieces are much smaller and don't overlap.

More detail

Recursion is the natural way to write divide and conquer, but naive recursion can be expensive, as Fibonacci shows. When subproblems overlap, use dynamic programming instead.

Source: Algorithms and Data Structures notes, section 5, pages 99–100.

Sequential search versus binary search

Sequential

Sequential(T[1..n], x)
  for i = 1 to n do
    if T[i] > x then return i − 1
  return n

Look at each item in turn. Time in the order of n. Not divide and conquer.

Binary

BinSearch(T[i..j], x)
  if i = j then return i
  k = (i + j + 1) div 2
  if x < T[k] then
    return BinSearch(T[i..k − 1], x)
  else return BinSearch(T[k..j], x)

Compare with the middle and throw half away. Time in the order of log n.

Searching for 30 in a sorted array of 16

30 < T[9] = 42: keep the left half

30 ≥ T[5] = 23: keep the right half

30 < T[7] = 39: keep the left half

30 ≥ T[6] = 27: keep T[6..6], so i = j: return 6

Remember: Binary search halves the range each step: 16 → 8 → 4 → 2 → 1, so about log₂ n comparisons.

More detail

T must be sorted. If x isn't present, both algorithms return the position where it would be inserted: the index i with T[i] ≤ x < T[i + 1] (0 ≤ i ≤ n). 30 isn't in the array, and 6 is right: T[6] = 27 ≤ 30 < T[7] = 39.

div is integer division; (i + j + 1) div 2 rounds the middle up, so T[k..j] always shrinks.

Looking a word up in a dictionary works the same way: open in the middle, then keep the half that must contain it.

Source: Algorithms and Data Structures notes, section 5, pages 101–104.

MergeSort

MergeSort(A[i..j])
  if i = j then return A[i..j]
  else
    m = (i + j) div 2
    U = MergeSort(A[i..m])
    V = MergeSort(A[m + 1..j])
    return Merge(U, V)

Divide into two halves, conquer each with MergeSort, combine with Merge. A sequence of length 1 is already sorted: that's where the recursion stops.

Merge

Merge([1, 5, 6, 8], [3, 4, 9, 10]) repeatedly takes the smaller of the two front items: 1 3 4 5 6 8 9 10. Time in the order of n.

Remember: MergeSort: split in half, sort each half, merge. log n levels of n work each: n log n.

More detail

The notes write the halves as A[i..⌊j/2⌋] and A[1 + ⌊j/2⌋..j], which is right for the first call (i = 1); in general the split point is the middle of i..j, as above.

A practical variant stops recursing when the piece is small and sorts it with InsertionSort, which is fast on short arrays: if j − i is small then InsertionSort(A[i..j]).

MergeSort's n log n holds in every case, best and worst, but merging needs extra memory for the merged copy.

Source: Algorithms and Data Structures notes, section 5, pages 105–110.

QuickSort

QuickSort(T[i..j])
  if i < j then
    l = Pivot(T[i..j])
    QuickSort(T[i..l − 1])
    QuickSort(T[l + 1..j])
  • Divide: rearrange around a pivot so everything left is smaller and everything right is at least as big
  • Conquer: QuickSort both sides
  • Combine: nothing to do: the array was sorted in place

Remember: QuickSort: n² in the worst case, n log n on average, and in practice usually the fastest sort, because its constants are small.

More detail

The array is treated as external to the pseudocode: calls pass only the index range, so no copies are made. That's why the combine step is free, unlike MergeSort.

In the notes' early sketch the pivot is the first item and joins the right-hand part; then a sorted input gives a lopsided tree. Rotating the choice of pivot (for example using the last item, or a random one) avoids always hitting the bad case. From the detailed version on, the pivot sits between the two parts.

Class examples from the lecture to try: apply Pivot in detail and draw the tree for 5, 6, 4, 3, 7; for 8, 7, 6, 5, 4, 3, 2, 1; and for 1, 2, 3, 4, 6, 7, 8, 9.

Source: Algorithms and Data Structures notes, section 5, pages 111–118, 123–125.

The Pivot procedure, step by step

Pivot(T[i..j])
  p = T[i]
  k = i
  l = j + 1
  repeat k = k + 1 until T[k] > p or k ≥ j
  repeat l = l − 1 until T[l] ≤ p
  while k < l do
    interchange T[k] and T[l]
    repeat k = k + 1 until T[k] > p
    repeat l = l − 1 until T[l] ≤ p
  interchange T[i] and T[l]
  return l

k moves right looking for something too big; l moves left looking for something small enough. Swap them, carry on until they cross, then put the pivot at l.

Example: 5 3 2 6 4 1 3 7

Start: p = T[1] = 5

k stops at T[4] = 6 > 5; l stops at T[7] = 3 ≤ 5; 4 < 7, so swap

k stops at T[7] = 6; l stops at T[6] = 1; 7 > 6, so stop and swap T[1] with T[6]

Return l = 6: the pivot 5 is in its final place; QuickSort continues on positions 1–5 and 7–8.

Remember: Pivot: two pointers walk inwards swapping misplaced pairs; when they cross, the pivot drops into the gap at l.

More detail

One scan of the array, from both ends at once: the Pivot procedure takes time in the order of n.

Positions are numbered from 1 here, as in the notes. After pivoting, everything in i..l − 1 is ≤ p and everything in l + 1..j is > p.

Source: Algorithms and Data Structures notes, section 5, pages 119–123.
