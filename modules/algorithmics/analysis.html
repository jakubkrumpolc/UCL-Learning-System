What is an algorithm, and why study them?

Definition

An algorithm is a well-defined computational procedure that takes input and gives output.

Input

Algorithm

Output

It pins down the relationship between input and output. Different algorithms can give the same relationship but have very different properties: speed, memory, simplicity.

Why study them?

ReasonBecause
Better than brute forceknowing the best way beats trying everything
Cross-fertilisationhow known algorithms work helps you design new ones
Efficiencyalgorithms for the same job can differ radically in time and space
Correctnessa precise specification lets you check the input/output behaviour

Remember: Same input and output, different algorithm, very different cost: choose an algorithm like choosing the right tool.

More detail

The course textbook (optional) is Cormen, Leiserson, Rivest and Stein, Introduction to Algorithms, 4th edition, MIT Press 2022. Sedgewick's books are another good source.

The notes recommend coding every algorithm in Python to see how it works. Pseudocode usually needs a little redesign first, for example because the notes number arrays from 1 and Python from 0.

Source: Algorithms and Data Structures notes, section 2, pages 4–8.

Part 1 · Measure

Pseudocode

The rules in this course

  • Not English: maximise clarity, minimise ambiguity
  • Not code: independent of machine and programming language, a higher-level view
  • Familiar keywords from C, Java, Python; bits of English and maths allowed
  • No break or goto, no classes, no type declarations
  • Choose the level of detail with care
OddTest(x)
  if x is odd then print "yes"
  else print "no"
PrintNumberSequence(x)
  n = 0
  while n ≤ x
    print n
    n = n + 1
PrintPairs(x)
  n = 0
  m = 0
  while n ≤ x
    while m ≤ x
      print n, m
      m = m + 1
    n = n + 1
    m = 0

PrintNumberSequence(5) prints 0 1 2 3 4 5; PrintPairs(2) prints all nine pairs from 0, 0 to 2, 2.

Remember: Pseudocode is precise enough to analyse and loose enough to ignore any one language.

More detail

Indentation shows which lines belong to which while or if, just as in Python.

There is no standard pseudocode. What matters is that a reader can follow every step and count them.

Source: Algorithms and Data Structures notes, section 2, pages 9–13.

Two ways to multiply

Repeated addition

Multiply(x, y)
  p = 0
  while y ≠ 0 do
    p = p + x
    y = y − 1
  return p

Add x to itself y times. 123 × 75 takes 75 cycles.

Multiplication by 2

Multiply(x, y)
  product = 0
  while y ≠ 0 do
    while y is even do
      x = x × 2
      y = y / 2
    product = product + x
    y = y − 1
  return product

If y is even, x × y = (2x) × (y / 2). If odd, take one x off first. 123 × 75 takes 7 cycles.

Remember: Halving the problem each step beats chipping one off: 7 cycles instead of 75.

More detail

Each cycle of the outer while adds one value of x to the product; in between, the inner loop doubles x and halves y as long as y is even. The product adds 123 + 246 + 984 + 7872 = 9225.

The number of cycles of the second method grows with the number of binary digits of y (about log₂ y), not with y itself. We need a general way to compare algorithms like this: that's the next section.

Measuring efficiency

What we measure

  • Resources: time and space (memory)
  • Analysed theoretically (counting) or empirically (timing runs)
  • Input size n: usually the number of items in the input
  • Running time: the number of elementary steps on a given input, a function of n

Which input?

Means
Worst casetime on the worst possible input of size n
Average casetime expected on a “typical” input
Best casetime on the most favourable input

For the worst case we look for a function f with f(n) = time taken on the worst input of size n.

Elementary operations

addition

subtraction

multiplication

division

modulo

Boolean operations

comparisons

assignments

Each of these counts as one unit of time, unless stated otherwise.

Remember: Running time = number of elementary steps, as a function of the input size n. Usually we quote the worst case.

More detail

Worst-case analysis gives a guarantee: the algorithm never takes longer. Average-case analysis needs an assumption about what typical inputs look like, which is harder to justify.

Treating every elementary operation as one unit is a simplification: real machines differ, but the simplification doesn't change how the running time grows, which is what we compare.

Source: Algorithms and Data Structures notes, section 2, pages 19–21, 32.

Greatest common divisor: obvious versus Euclid

Obvious

GCD(m, n) is the largest integer that divides both exactly: GCD(6, 15) = 3, GCD(120, 700) = 20, GCD(9, 0) = 9. If it is 1, m and n are coprime: GCD(10, 21) = 1.

GCD(m, n)
  i = min(m, n) + 1
  repeat
    i = i − 1
  until i divides both m and n exactly
  return i

Straight from the definition: try every candidate downwards. Up to min(m, n) steps.

Euclid (n ≥ m > 0)

Euclid(m, n)
  while m > 0 do
    t = n mod m
    n = m
    m = t
  return n
Cycletnm
start156
115 mod 6 = 363
26 mod 3 = 030
3return 3

Based on GCD(x, y) = GCD(x − y, y) for x > y; mod subtracts as many y's as possible at once.

Remember: Euclid: replace (m, n) by (n mod m, m) until m is 0; what's left in n is the GCD.

More detail

The subtraction version shown in the notes on GCD(10, 8): subtract y from x while x > y, swapping when x < y: (10, 8) → (2, 8) → swap (8, 2) → (6, 2) → (4, 2) → (2, 2), done: the GCD is 2. Euclid's mod does all the repeated subtractions in one step.

Euclid's algorithm takes a number of cycles proportional to the number of digits, far fewer than the obvious algorithm on large numbers.

Source: Algorithms and Data Structures notes, section 2, pages 24–27.

Fibonacci: recursion versus iteration

Fibonacci(n)
  if n ≤ 2 then return 1
  else return Fibonacci(n − 1) + Fibonacci(n − 2)

The same values are computed again and again (orange): the number of calls grows exponentially.

Fibonacci2(n)
  i = 1
  j = 0
  for k = 1 to n do
    j = i + j
    i = j − i
  return j
k123456
j112358
i011235

Keep the last two values and step forward: linear time.

Recursion

A recursive algorithm solves a problem by solving a simpler version of the same problem with the same program, as in factorial and Fibonacci. Recursive definitions are clear and elegant, but can be inefficient because of repeated computation.

Remember: Elegant recursion can be exponentially slow when it recomputes the same subproblems; a loop that remembers is linear.

More detail

The sequence is 1, 1, 2, 3, 5, 8, 13, 21, …: each term after the first two is the sum of the previous two.

Storing answers to subproblems so they're never recomputed is the idea behind dynamic programming.

Source: Algorithms and Data Structures notes, section 2, pages 28–31.

Insertion sort

InsertionSort(A)
  for (j = 2 to Length(A)) do
    temp = A[j]
    i = j − 1
    while (i > 0 and A[i] > temp) do
      A[i + 1] = A[i]
      i = i − 1
    A[i + 1] = temp
  return A

Arrays in the notes are numbered from 1: T[1] = 3, T[2] = 8, … for the list 3 8 14 99 53 2.

Example: 5 2 4 6 1 3

Take A[j] out (temp), shift the bigger sorted items right, drop temp into the gap. A[1..j − 1] is always sorted.

Remember: Insertion sort grows a sorted prefix, inserting each next item into place like sorting a hand of cards.

More detail

Pale cells are the sorted prefix; the bright cell is the next item A[j] to insert. Index labels under the boxes count from 0, as in Python; the notes count from 1.

The while loop's i pointer walks left from j − 1, shifting each item bigger than temp one place right. For j = 2 on 5 2 4 6 1 3: 5 > 2 so 5 shifts right, i becomes 0, and 2 goes into position 1.

Source: Algorithms and Data Structures notes, section 2, pages 33–36.

Best

Best case: already sorted, 1 2 3 … n. The while test fails at once: tⱼ = 1.

T(n) = (c₁ + c₂ + c₃ + c₄ + c₇) n − (c₂ + c₃ + c₄ + c₇): linear.

Worst

Worst case: reverse order, n … 2 1. Each item is compared with the whole sorted part: tⱼ = j.

Using Σⱼ₌₂ⁿ j = n(n + 1)/2 − 1 and Σⱼ₌₂ⁿ (j − 1) = n(n − 1)/2, T(n) = (c₄/2 + c₅/2 + c₆/2) n² + … : quadratic.

Remember: Insertion sort: linear when already sorted, quadratic when reversed. tⱼ counts the while-tests for item j.

More detail

A statement with cost cᵢ that runs k times contributes cᵢ·k to the total running time T(n); add up all seven lines.

Line 1's test runs n times (succeeds n − 1 times, fails once to end the loop), so lines 2, 3 and 7 run n − 1 times. Likewise line 4 is tested tⱼ times for item j, and its body (lines 5 and 6) runs tⱼ − 1 times.

The summations come from 1 + 2 + … + n = n(n + 1)/2.

Source: Algorithms and Data Structures notes, section 2, pages 37–43.

Optimisation problems

Find the best, not just any

Many problems have many solutions, and each can be measured. Optimisation means finding a solution with the best (minimum or maximum) value.

Example

Driving from London to Edinburgh: there are many routes. The optimal one depends on the measure: shortest distance, fastest time, or lowest fuel use.

Remember: An optimisation problem asks for the best solution by some measure; change the measure and the answer changes.

More detail

Greedy algorithms (Part 3) and dynamic programming (Part 5) are the two main techniques in this course for optimisation problems.

Source: Algorithms and Data Structures notes, section 2, page 44.
