Strings: indexing and slicing

c = "linguistics"
print(c[2])
s1 = "vocabulary"
print(s1[-1], s1[-2])
n
y r
string[start:end]     # end not included

Slices

my_string = "It is a sunny day!"
print(my_string[3:12])
print(my_string[1:])
print(my_string[:])
print(my_string[-50:70])
is a sunn
t is a sunny day!
It is a sunny day!
It is a sunny day!
  • Leave out start: from the beginning. Leave out end: to the end
  • [:] copies the whole string
  • Indexes past either end are cut down to fit: no error

Remember: s[a:b] is from position a up to, but not including, b; s[-1] is the last character.

More detail

Index 12 in “It is a sunny day!” is the y of “sunny”, which is why [3:12] stops at sunn. Count from 0: I(0) t(1) space(2) i(3) s(4)…

A single index past the end is an error ("abc"[5] raises IndexError); only slices are forgiving.

Two variables made from the same short literal often share one object: strA = "Good"; strB = "Good" gives strA is strB → True and the same id(). That's a CPython memory optimisation (interning); compare strings with ==.

Source: Lecture 5, “Strings are arrays”, “Negative indexing”, “String slicing”, “Strings representation in memory”.

Remember: find says −1 when it fails; index raises an error. Both are case-sensitive.

More detail

Every string method returns a new string (or a number); none changes the original, because strings are immutable. Keep the result: name = name.strip().

Other methods worth knowing: s.split() (cut into a list of words), "-".join(words) (glue a list into one string), s.startswith("x"), s.endswith("x"), s.count("x"), s.isdigit(), s.title(). The full list is in the Python docs under “Text Sequence Type — str”.

Mutable and immutable types

Strings can't change

st = "Hello"
print(st.replace('H', 'B'))
print(st)
st[2] = 'r'
Bello
Hello
TypeError: 'str' object does not support item assignment

replace made a new string; st itself never changed.

Which is which

Immutable (can't change)Mutable (can change)
int, float, complex, boollist
strdict
tupleset
frozenset, bytesbytearray

Only immutable values can be dictionary keys or set items.

GroupTypes
Numericint 42 · float 3.14 · complex 3+4j
Sequencestr 'hello' · list [1, 2, 3] · tuple (1, 2, 3)
Mappingdict {'name': 'Alice', 'age': 25}
Setset {1, 2, 3} · frozenset frozenset([1, 2, 3])
Boolean · Nonebool True, False · NoneType None (no value)
Binarybytes b'hello' · bytearray · memoryview

Remember: Immutable values are replaced, never changed: “changing” a string really makes a new one.

More detail

Why it matters: if two names refer to the same list, a change through one is visible through the other (a = [1]; b = a; b.append(2) → a is [1, 2]). With an immutable value that can't happen; you can only make a name refer to a different value.

This is also why list methods return None (they change the list) and string methods return a new string (they can't). See Methods return None.

Source: Lecture 5, “Strings are immutable”, “Summary of Python datatypes”, “Mutable and immutable data types”.

Part 5 · Define

Functions: give a piece of work a name

def function_name(parameters):
    function body
def my_function():
    print("Hello World!")

my_function()      # call it
my_function()      # and again
Hello World!
Hello World!

Why use functions?

A function is a named section of a program that does one specific task.

  • Reusability: write it once, call it whenever you need it, no copy-pasted code
  • Abstraction: use a function without knowing how it works inside (you use print every day), and let others use yours

Remember: def only defines the function; nothing runs until you call it with brackets: name().

More detail

Without the brackets, my_function is just the function object itself, which you can pass around or store (see functions as values). my_function() runs it.

A function must be defined before the line that calls it runs, so definitions usually go at the top of the file.

Parameters are the names in the def line; arguments are the values you pass when you call it.

Source: Lecture 5, “Functions”, “Why use functions?”, “Creating a function”, “Calling a function”.

Part 5 · Define

Arguments: required, default and keyword

Required

def my_function(name, age):
    print("Hello %s. Your age is %d." % (name, age))

my_function("Marge", 36)
Hello Marge. Your age is 36.

Must be given, in order. Missing one is a TypeError.

Default

def my_function(module="Programming"):
    print("I am studying " + module)

my_function("Mathematics")
my_function()
I am studying Mathematics
I am studying Programming

Used only when the caller leaves it out.

Keyword

def my_function(name, age, course):
    print("The student is studying", course)

my_function(age=23, course="Computing",
            name="John Doe")
The student is studying Computing

Named with key=value, so order doesn't matter.

Data structures as arguments

def show(books):
    for title in books:
        print(title)

show(["Pride and Prejudice", "1984", "The Great Gatsby"])

Any value can be an argument, including a list, string or dictionary; the function uses it like any other value.

Remember: Required first, in order; defaults fill gaps; keywords let you name them in any order.

More detail

Parameters with defaults must come after those without: def f(a, b=2) is fine, def f(a=1, b) is a SyntaxError.

When you pass a list to a function and the function changes it (books.append(...)), the caller sees the change, because both names refer to the same list. Strings and numbers can't be changed that way.

Source: Lecture 5, “Function arguments”: required, default, keyword; “Data structures as parameters”.

Part 5 · Define

*args and **kwargs: any number of arguments

*args

def adder(*num):
    total = 0
    for n in num:
        total = total + n
    print("Total:", total)

adder(3, 5)
adder(4, 5, 6, 7)
adder(1, 2, 3, 5, 6)
Total: 8
Total: 22
Total: 17

*num collects every extra positional argument into a tuple.

**kwargs

def my_function(**kwargs):
    for key, value in kwargs.items():
        print("%s == %s" % (key, value))

my_function(first="John", mid="Smith", last="Doe")
first == John
mid == Smith
last == Doe

**kwargs collects every extra keyword argument into a dictionary.

Remember: One star gathers a tuple of values; two stars gather a dictionary of name=value pairs.

More detail

The names args and kwargs are only conventions; the stars do the work. *num works just as well.

The stars also work the other way round when calling: adder(*[1, 2, 3]) unpacks a list into separate arguments, and f(**{'a': 1}) unpacks a dictionary into keyword arguments.

Order in a def line: normal parameters, then *args, then keyword parameters, then **kwargs.

Source: Lecture 5, “Variable-length arguments”, “*args”, “**kwargs”.

Part 5 · Define

Return values

def add(num1, num2):
    return num1 + num2

total = add(10, 20)
print(total)
30
def my_function(*words):
    word_list = []
    for w in words:
        word_list.append(w)
    return word_list

print(my_function("London", "Paris", "Madrid"))
['London', 'Paris', 'Madrid']

The rules

  • return sends a value back to the caller and ends the function
  • Any type can be returned; several values come back as a tuple: return lo, hi
  • No return (or a bare return) gives back None
  • pass is a placeholder body: def todo(): pass

Functions as values

def greet(name):
    return f"Hello, {name}!"

actions = {"greet": greet}
print(actions["greet"]("Sam"))
Hello, Sam!

Functions are values too: store them in a dictionary and call them by key.

Remember: print shows a value to the user; return hands it back to the code. Only returned values can be stored.

More detail

In a notebook, calling add(10, 20) on its own line shows 30 because Jupyter displays the value of the last expression in a cell. In a normal .py program nothing appears unless you print it.

A common mistake: a function that prints its answer instead of returning it. x = f() then stores None.

f"Hello, {name}!" is an f-string: the expression in braces is put into the text.

Source: Lecture 5, “Return values”, “The pass statement with functions”, “Using a function as dictionary value”.

Part 5 · Define

Scope: which variable does Python mean? (LEGB)

B · Built-in · print, len, abs…

G · Global · top level of the file

E · Enclosing · the function around it

L · Local · names made inside this function

Python looks for a name from the inside out and uses the first one it finds.

x = 150
y = 170

def fun(x):
    y = 100        # a new, local y
    print(x, y)

fun(93)
print(x, y)
93 100
150 170
e = 992

def foo(e):
    f = 100
    def bar():
        print(e, f)   # found in foo: enclosing
    bar()

foo(77)
print(e)
77 100
992

Remember: LEGB: Local, Enclosing, Global, Built-in. Inside out, first match wins.

More detail

In fun, both x (the parameter) and y (assigned inside) are local, so the global x = 150 and y = 170 are untouched. Outside the function there is no local scope, so print(x, y) sees the globals.

Built-in names such as print, len and abs are found last. If you define your own abs, yours is found first and hides the built-in one. print(dir(__builtins__)) lists every built-in name.

A name must exist before it's used: print(s) followed by s = 15 raises NameError.

Source: Lecture 5, “Variable scope”, “LEGB scope rules”, “Local scope”, “Enclosing scope”, “Built-in Scope”.

Part 5 · Define

global, and blocks that don't make a scope

global

def fun():
    global z
    z = 100

fun()
print(z)
100

global z makes the assignment create or change the global z. The function must be called first: without fun(), print(z) is a NameError.

No new scope

a = -10
if a > 0:
    b = 17

print(b)
NameError: name 'b' is not defined

if, elif, else, for and while don't create a scope: a variable made inside is a normal global variable, but only if the block actually runs.

Remember: Only functions make a new scope. if and loops don't, but their variables exist only if the block ran.

More detail

Without global, assigning to a name inside a function always makes a new local variable, even if a global with that name exists. Reading a global without assigning to it works without global.

Use global sparingly: functions that change globals are hard to follow. Prefer passing values in as arguments and returning results.

In Jupyter, a variable from an earlier run of a cell stays defined, so code like the if example can seem to work. Restart the kernel to check.

Source: Lecture 5, “Keyword global”, “Must enter function scope”, “No new scope”.
