Part 1 · Values

Your first program: print()

print("Hello World!")
print(2027)
print(13.4)
Hello World!
2027
13.4

What print does

print() shows a value on the screen, then moves to a new line.

Give it several values separated by commas and it prints them on one line, with a space between each:

print("Total:", 3, 4.5)
Total: 3 4.5

Remember: print() shows a value but doesn't keep it. To keep a value, give it a name.

More detail

Text must be inside quotes, numbers must not be: print(2027) prints a number, print("2027") prints text that looks like a number. The difference matters as soon as you calculate with it.

print has two useful optional arguments: sep (what goes between values, a space by default) and end (what goes after the last one, a new line by default). print(1, 2, 3, sep="-") prints 1-2-3; print("a", end="") stays on the same line.

Source: Lecture 1, “Your first program”.

Part 1 · Values

Variables: names for values

name   = "James Bond"   # a string
age    = 35             # an integer
height = 1.82           # a float

print(name)
print(age)
print(height)
James Bond
35
1.82

Assignment

A variable is a name that refers to a value stored in memory. = binds the name on the left to the value on the right.

name = value

Use the name anywhere you would write the value.

Chained assignment

a = b = c = 5

Chained: one value, several names. All three are 5.

Many at once

a, b, c = 10, -70, "cat"

Multiple: values matched to names by position.

Re-assigning

a = 100
a = "Python"

Re-assigning: the name now refers to the new value, even of a different type.

Remember: = means “let this name refer to this value”, not “equals”. Read it right to left.

More detail

Because the right-hand side is worked out first, x = x + 1 makes sense: take the value of x, add 1, and make x refer to the result.

Multiple assignment needs the same number of names and values: a, b = 1, 2, 3 raises ValueError: too many values to unpack. It also gives a neat swap: a, b = b, a.

Source: Lecture 1, “Variables and assignments”, “Chained assignment”, “Re-declaring variables”.

Naming rules and naming style

Rules: break one and it's a SyntaxError

  • Letters, digits and underscore only: a-z A-Z 0-9 _
  • Must start with a letter or _: 56_var is invalid
  • No spaces: my var is invalid
  • Not a reserved word such as else, for or class
  • Case matters: age54 and Age54 are two variables
  • Letters from other alphabets are allowed: cumpleaños, π

Style: Python won't complain, but readers will

  • Use lower_case_with_underscores (snake case), as PEP 8 recommends
  • Pick names that say what the value is: total_price, not tp
  • Keep them a sensible length
  • Never use l, O or I alone: they look like 1 and 0
NameValid?Why
country_of_residenceYesletters and underscores
4rNostarts with a digit
elseNoreserved word
α, πYesGreek letters are letters
♥Noa symbol, not a letter

List every reserved word:

import keyword
print(keyword.kwlist)

Or type help('keywords') in the interpreter.

Remember: Letters, digits and underscores; never start with a digit; never a keyword; case matters.

More detail

Python 3 lets names use Unicode letters, so cumpleaños = "birthday" works, but symbols like ♥ are not letters and are rejected. In shared code, stick to plain English letters so everyone can type the names.

PEP 8 is Python's official style guide (python.org/dev/peps/pep-0008). Following it doesn't change what your code does, but it makes it easier to read and therefore to maintain.

Source: Lecture 1, “Rules for naming variables”, “Python reserved words list”, “Naming style”.

Dynamically typed, strongly typed

Dynamic

Types are found at run time

The type belongs to the value, not to the name, and is worked out when the code runs. You never declare it, and a name can later refer to a value of another type.

a = 100       # int
b = 100.0     # float
c = "Hello"   # str

Statically typed languages such as Java make you declare the type first: int a = 100;

Strong

No implicit mixing

Python won't silently mix unrelated types. Adding a number to a string is an error, not a guess.

a = 100
b = "200"
print(a + b)
TypeError: unsupported operand type(s) for +: 'int' and 'str'

A weakly typed language such as JavaScript would give "100200".

Remember: Dynamic: the type travels with the value, not the name. Strong: Python never guesses how to mix types.

More detail

“Dynamic” and “strong” answer different questions. Dynamic versus static is about when types are checked (while running, or before). Strong versus weak is about whether the language converts between unrelated types for you. Python is dynamic and strong; Java is static and strong; JavaScript is dynamic and weak.

Python does convert between related types, such as int and float, because no information is lost (see Type conversion).

Source: Lecture 1, “Python is dynamically typed”, “Python is strongly typed”.

Comments and indentation

Comments are for people

a = 100  # a is a variable
print(a)  # printing the value of a
b = "Hello #"  # this # is just text
  • A comment starts with # and runs to the end of the line; Python ignores it
  • A # inside a string is just a character
  • No block-comment syntax: start every line with #, or select lines and press Ctrl+/ (⌘/ on a Mac) in PyCharm
  • Commenting a line out is a quick way to stop it running without deleting it

Indentation is for Python

cities = ["tokyo", "oslo", "dakar"]
for c in cities:
    if c == "dakar":
        print("Found African city.")
    print(".")
  • A block (the body of an if, a loop, a function) starts with an indented line and ends at the first line that isn't
  • Indent with four spaces (or a tab), the same throughout a block
  • Wrong indentation changes the meaning or raises IndentationError

Remember: # talks to people; indentation talks to Python. Four spaces per level, always the same.

More detail

In the example, print(".") is indented once, so it belongs to the for loop and runs for every city. print("Found African city.") is indented twice, so it belongs to the if and runs only for Dakar. Output: ., ., Found African city., ..

The lecture mentions a “fix” for block comments using triple quotes """…""". That is really an unused string, which Python evaluates and throws away. It works, but # on each line is the proper way; triple-quoted strings are meant for docstrings (descriptions at the top of functions and classes).

Never mix tabs and spaces in one file: they can look identical in the editor and still confuse Python. Most editors insert four spaces when you press Tab.

Source: Lecture 1, “Comments in python code”, “Indentation”.

Numbers: int, float and complex

TypeExamplesWhat to know
int45, -22, 0Whole numbers, positive or negative. No size limit in Python 3, only memory.
float10.0, 22.657, 1.443E5Real numbers with a decimal point, accurate to about 15 decimal digits. 1.443E5 means 1.443 × 10⁵ = 144300.
complex-4.37 + 5jA real part and an imaginary part; j is √−1. Rarely needed.

Big integers

import sys
print(sys.maxsize)
9223372036854775807

sys.maxsize is the largest index a list can have on a 64-bit machine. Python's own ints can go far beyond it: try print(2 ** 100).

Same number, three types

print(type(3))
print(type(3.0))
print(type(3 + 0j))
<class 'int'>
<class 'float'>
<class 'complex'>

The decimal point alone makes a float.

Remember: int is exact and unlimited; float is approximate; complex has a j.

More detail

Python 2 had separate int and long types. Python 3 has one int that grows as needed, so overflow is not something you need to think about.

Underscores can make long numbers readable: 1_000_000 is the same as 1000000.

Source: Lecture 1, “Integers”, “Floating point numbers”, “Complex numbers”.

Part 1 · Values

Never compare floats with ==

a = 1.2
b = 1.0
print(a - b)
print(a - b == 0.2)
0.19999999999999996
False

Most decimals can't be stored exactly in binary, so tiny errors creep in. The test == 0.2 fails even though the maths says it's true.

Compare with a tolerance

e = 0.0000001  # epsilon: how close is close enough

if 0.2 - e <= (a - b) <= 0.2 + e:
    print("do something.")

Check the difference is smaller than a tolerance instead.

import math
math.isclose(a - b, 0.2)   # True

math.isclose does the same test for you.

Remember: Floats are close, not exact: compare them with a tolerance, never with ==.

More detail

The same thing happens with 0.1 + 0.2, which prints 0.30000000000000004. It isn't a Python bug: every language that uses binary floating point (almost all of them) behaves this way. The Python tutorial page “Floating Point Arithmetic: Issues and Limitations” explains why.

For money, where every penny must be exact, use whole numbers of pennies (ints) or the decimal module.

Source: Lecture 1, “Floating point arithmetic limitations”, “Consequences”.

Booleans and strings

bool

a = True
b = 12
print(b > 10)
print(b < 5)
True
False

Two values: True and False, with capitals. Comparisons produce them; if statements and loops use them.

str

print('Hello 34 World!')
print("and 'another' string")
print('')   # the empty string
  • A string is a sequence of characters, in single or double quotes
  • Use one kind of quote to include the other
  • There's no separate character type: 'A' is a string of length 1
WriteTo get
\na new line
\ta tab
\' \"a quote that doesn't end the string
\\one backslash
r"\n"a raw string: backslashes stay as typed
print("First line.\nSecond line.")
First line.
Second line.
print("""Line one
Line two""")
Line one
Line two

Triple quotes (''' or """) make multi-line strings, and quotes inside need no escaping.

Remember: A backslash makes the next character special (\n), or stops it being special (\'). r"…" turns that off.

More detail

Escape sequences are worked out when Python reads the string, so len("a\nb") is 3: the \n is one character.

Raw strings are handy for Windows paths and regular expressions, where backslashes are common: r"C:\new\folder" keeps \n as two characters instead of a new line.

Source: Lecture 1, “Booleans”, “Strings”, “Escape sequences”, “Triple-quoted strings”.

String operators and % formatting

OperatorMeanings = "Hello "
+join two stringss + "World!" → Hello World!
*repeats * 3 → Hello Hello Hello
[i]one character, counting from 0s[2] → l
[i:j]a slice: from i up to, not including, js[1:3] → el
in, not inis it inside?'el' in s → True

Indexes start at 0

s[1:3] takes positions 1 and 2. The end position is never included.

name, age, height = "Anna", 33, 1.757456456
print("Your name is %s, your age is %d, and your height is %.2f"
      % (name, age, height))
Your name is Anna, your age is 33, and your height is 1.76

Format flags

FlagInserts
%sa string (or anything)
%dan integer
%fa float
%.2fa float, 2 decimals
%x %Xhex: 5b7f / 5B7F

Remember: Slices include the start and exclude the end: s[1:3] is two characters.

More detail

The % operator puts values into a string: each flag is replaced, in order, by the values in the tuple after %. With one value the brackets are optional: "A week has %d days" % 7.

Modern Python more often uses f-strings, which do the same job more readably: f"Your name is {name}, your age is {age}, and your height is {height:.2f}". You'll meet .format() in the OOP lecture: "Hi {}".format(name).

Strings can't be changed in place: s[0] = "J" is an error. You build a new string instead (see mutable and immutable types).

Source: Lecture 1, “String operators”, “The format operator %”, “Format operators flags”.

Part 1 · Values

type() and id()

type(): what is it?

print(type("Hello"))
print(type(45.5))
print(type(True))
print(type(78.98 + 62))
<class 'str'>
<class 'float'>
<class 'bool'>
<class 'float'>

type(x) tells you what kind of value x is. It works on whole expressions too. Mostly used when debugging.

id(): which object exactly?

x = 123
y = "Hello"
z = 123
print(id(x), id(y), id(z))

id(x) gives the object's unique number while it exists. Two objects that exist at the same time never share an id; objects with non-overlapping lifetimes may.

Here x and z print the same id: both names refer to the one object 123.

Remember: type() asks “what kind?”; id() asks “which one?”.

More detail

x is z compares ids (same object?), while x == z compares values (same contents?). See identity operators.

CPython keeps one shared object for each small integer (−5 to 256) and for many short strings, which is why x and z share an id above. Don't rely on it: use == to compare values.

Source: Lecture 1, “type() and id()”.

Type conversion: implicit and explicit

Implicit

Python does it

a = 5
b = 3
print(a / b)
1.6666666666666667

Python converts automatically when nothing can be lost: int to float, never the other way.

a = 10
b = "45"
print(a + b)
TypeError: unsupported operand type(s) for +: 'int' and 'str'

int + str has no safe answer, so you must convert yourself.

Explicit (casting)

You do it

a = 10
b = "45"
print(a + int(b))
55
new_type(expression)
CallResult
float(10)10.0
int(8.89)8 (cut off, not rounded)
str(787.44)'787.44'
float("567.65")567.65
int("3.5")ValueError

Remember: Python widens types for you (int → float); narrowing (float → int) and str ↔ number are your job.

More detail

int() throws away the fractional part: int(56.0909709) is 56, and int(-2.7) is -2. To round to the nearest whole number use round().

Casting is how you use what the user types, because input() always returns a string: age = int(input("Age: ")). See Taking input.

int("3.5") fails because "3.5" isn't written like an integer; int(float("3.5")) works.

Source: Lecture 1, “Type conversion (Casting)”.
