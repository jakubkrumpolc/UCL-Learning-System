Data structures: four built-in collections

A data structure is a way of organising data so that some operations are easy or fast. Python has four general-purpose ones built in; you'll build your own with classes in Part 7.

WrittenOrdered?Changeable?Duplicates?Good for
list[10, 20, 30]yesyesyesa sequence you add to and change
tuple(10, 20, 30)yesnoyesa fixed group of values, e.g. a date
set{10, 20, 30}noyesnouniqueness and fast “is it in?” tests
dict{'john': 4139}by insertionyeskeys: nolooking up a value by a key

Remember: List = shopping list, tuple = date of birth, set = guest list, dict = phone book.

More detail

Data structures and algorithms go together: the right structure can make an algorithm much faster. That's a central theme of Algorithmics.

Built-in data structures come with the language; user-defined ones are classes you write for a particular task.

Source: Lecture 4, “Data structures”, “Python built-in data structures”.

Lists: ordered and changeable

listA = []                    # empty list
listB = [10, 20, 30]          # integers
listC = [10, "word", 7.5]     # mixed types
print(listC)
[10, 'word', 7.5]
simpleList = [3, 'ok', 10.5, 'python', True]
print(simpleList[4])
print(simpleList[5])
True
IndexError: list index out of range

Indexing

A list of N items has indexes 0 to N − 1. Anything else raises IndexError.

Changing an item

my_list = [1, 2, 3]
my_list[0] = 125
print(my_list)
[125, 2, 3]

Lists are mutable: you can change an item in place.

Looping over a list

for chemical in ['Oxygen', 'Carbon', 'Zinc']:
    print(chemical)
Oxygen
Carbon
Zinc

Remember: Square brackets make a list and also read from it: items[0] is the first, items[len(items) - 1] the last.

More detail

A list can hold anything, including other lists and mixed types, but in practice lists usually hold items of one kind (all names, all marks) so you can treat them the same way in a loop.

len(items) gives the number of items, so the last valid index is len(items) - 1.

Source: Lecture 4, “Lists”, “Accessing an element of a list by index”, “Lists are mutable”.

Negative indexes and nested lists

Counting from the end

myList = ['w', 'o', 'r', 'l', 'd']
print(myList[-1])
print(myList[-2])
d
l

-1 is always the last item, whatever the length. s[:-1] is everything except the last item.

Lists inside lists

nestedList = ["tree", [5, [10, 40, 60], 20], ['g']]
print(nestedList[1])
print(nestedList[1][2])
print(nestedList[1][1][0])
[5, [10, 40, 60], 20]
20
10

Read the indexes left to right: nestedList[1] is the inner list, then [2] picks from that.

Remember: [-1] is the last item. For nested lists, one pair of brackets per level, outermost first.

More detail

Brackets after a value are always an index; brackets on their own make a list. Context tells them apart: [1, 2][0] makes a list and then takes its first item.

line[:-1] is a common way to drop the newline at the end of a line read from a file (though line.rstrip("\n") is safer).

Source: Lecture 4, “Nested lists”, “Negative indexing”.

Methods that change a list return None

What went wrong

nbList = [4, 7, 1, 2]
nbList = nbList.sort()
print(nbList)
None

sort() sorted the list in place and returned None, which was then assigned to nbList. The sorted list is lost.

Two right ways

nbList.sort()               # sort the list itself

new = sorted(nbList)        # or make a sorted copy
nbList = [4, 7, 1, 2]
print(sorted(nbList), nbList)
[1, 2, 4, 7] [4, 7, 1, 2]

Remember: L.sort() changes L and gives back nothing; sorted(L) gives back a new list and leaves L alone.

More detail

The same is true of append, insert, remove, reverse and clear: lists are mutable, so these methods change the list directly and have nothing to return. Never write L = L.append(x).

String methods are the opposite: strings can't change, so s.upper() returns a new string and you must keep it: s = s.upper().

Source: Lecture 4, “Note on List methods”.

List comprehensions: build a list in one line

[expression for item in iterable if condition]

With a loop

doubles = []
for i in range(7):
    doubles.append(i * 2)
print(doubles)
[0, 2, 4, 6, 8, 10, 12]

As a comprehension

doubles = [i * 2 for i in range(7)]
print(doubles)
[0, 2, 4, 6, 8, 10, 12]

With a condition

evens = [n * n for n in range(10) if n % 2 == 0]
print(evens)
[0, 4, 16, 36, 64]
dissimilarPairs = [(x, y) for x in [1, 2, 3] for y in [3, 1, 4] if x != y]
print(dissimilarPairs)
[(1, 3), (1, 4), (2, 3), (2, 1), (2, 4), (3, 1), (3, 4)]

Remember: Read a comprehension as “give me this for each item in that if it passes”.

More detail

A comprehension always makes a new list and leaves the original unchanged. The if part is optional.

Two fors work like nested loops, outer one first: the pairs example is the same as for x in [1, 2, 3]: for y in [3, 1, 4]: if x != y: pairs.append((x, y)).

Keep them short. If a comprehension doesn't fit comfortably on one line, a normal loop is clearer.

Source: Lecture 4, “List Comprehensions”.

Tuples: lists that can't change

Making a tuple

t1 = (1, 2, 3)
t2 = 1, 2, 3                 # brackets optional
t3 = ('Hello', 23, (1, 2, 3))
empty = ()
single = (11,)               # the comma makes it a tuple
t1[0] = 9
TypeError: 'tuple' object does not support item assignment

Packing, unpacking, and what works

x = ('Dell', 2000, 'Computing')     # packing
(company, emp, activity) = x        # unpacking
print(company)
Dell
  • Indexing, slicing, len, in and loops all work
  • append, remove, item assignment don't
  • del t deletes the whole tuple; you can't delete one item

Remember: Tuples are read-only lists. A one-item tuple needs a comma: (11,).

More detail

Why have an unchangeable list? Integrity: values that belong together and shouldn't change, like a date or a coordinate, can't be altered by accident. Tuples can also be dictionary keys, which lists can't.

(11) is just the number 11 in brackets, so type((11)) is int. It's the comma, not the brackets, that makes a tuple. (The lecture notebook's output shows <class 'int'> because it was run before the comma was added.)

A tuple can contain a mutable object such as a list, and that list can still change: t = (5, ['a', 'b'], 'ok'), then t[1].append('c') works. The tuple still holds the same list; the list changed.

Source: Lecture 4, “Tuples”, “Tuple packing and unpacking”, “Why tuples?”.

Sets: no duplicates, no order

basket = {'milk', 'soap', 'pen', 'milk'}
print(basket)
print('soap' in basket)
{'soap', 'pen', 'milk'}
True
anotherSet = set(['a', 'b', 'c', 'b'])
print(anotherSet)
{'a', 'b', 'c'}
  • Curly brackets, or set(...) from any sequence
  • Duplicates are removed automatically
  • No order, so no indexing: basket[0] is an error
  • Very fast membership tests with in

Set algebra

WriteGivessetA = set('abracadabra'), setB = set('alacazam')
A - Bdifference{'b', 'd', 'r'}
A | Bunion{'a', 'b', 'c', 'd', 'l', 'm', 'r', 'z'}
A & Bintersection{'a', 'c'}
A ^ Bsymmetric difference{'b', 'd', 'l', 'm', 'r', 'z'}

Watch out: {} is an empty dictionary, not an empty set. An empty set is set().

Remember: A set keeps one of each and forgets the order: perfect for removing duplicates and for “is it in?”.

More detail

Sets print in an unpredictable order, which can change between runs. The results above are shown sorted.

set('abracadabra') makes a set of the string's letters, because a string is a sequence of characters.

Set items must be immutable (numbers, strings, tuples), so you can't put a list in a set.

The lecture's example mySet = {} with the comment “empty set” actually makes an empty dictionary; type(mySet) shows <class 'dict'>.

Source: Lecture 4, “Sets”, “Set methods”.

Dictionaries: look a value up by its key

phoneBook = {'melissa': 4098, 'john': 4139}

phoneBook['andy'] = 4127         # add a pair
print(phoneBook['melissa'])      # look up
del phoneBook['john']            # delete a pair
phoneBook['melissa'] = 6789      # replace a value
print(phoneBook)
4098
{'melissa': 6789, 'andy': 4127}

Useful operations

WriteGives
list(d.keys())['melissa', 'andy']
sorted(d.keys())['andy', 'melissa']
sorted(d.values())[4127, 6789]
'andy' in dTrue (checks keys)
d['zoe']KeyError: 'zoe'
d.get('zoe', 0)0: a default instead of an error

Rules

  • Keys are unique: storing under an existing key replaces the old value
  • Keys must be immutable: strings, numbers, tuples
  • Values can be anything, including lists and other dicts

Looping over pairs

for name, number in phoneBook.items():
    print(name, number)

Remember: A dictionary maps keys to values: d[key] reads, d[key] = value writes, del d[key] removes.

More detail

The lecture describes dictionaries as unordered. Since Python 3.7 they keep the order in which keys were added, which is why phoneBook prints melissa before andy. Still, you look values up by key, never by position.

dict() also makes a dictionary: dict(melissa=4098, john=4139). Don't name a variable dict, as the lecture example does: it hides the built-in dict() function for the rest of the program.

Looking up a key is very fast however big the dictionary is, which is why dictionaries are everywhere in Python.

Source: Lecture 4, “Dictionaries”.
