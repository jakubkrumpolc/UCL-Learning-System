Exceptions: errors while the program runs

myList = ["Red", "Green", "Blue"]
print(myList[4])

print("Done")   # never reached
IndexError: list index out of range

An exception is an unusual condition that needs special handling. If nothing handles it, Python stops the program and prints the error, so the lines after it never run.

Common built-in exceptions

ExceptionRaised by
ZeroDivisionError12 / 0
ValueErrorint("abc")
IndexErrormyList[4] on 3 items
KeyErrord["missing"]
TypeError100 + "200"
NameErroran undefined name
FileNotFoundErroropen("nope.txt")

Remember: An unhandled exception ends the program on the spot. Handling it lets the program carry on.

More detail

Every exception type is a class, and they form a hierarchy: ZeroDivisionError is a kind of ArithmeticError, which is a kind of Exception. The full tree is in the Python docs, “Built-in Exceptions → Exception hierarchy”. Catching a parent catches all its children.

Exceptions are different from syntax errors: a SyntaxError or IndentationError is found before the program starts, and no try can catch it in the same file.

Source: Lecture 6, “What is an exception?”, “Built-in exception types”.

Part 6 · Handle

try and except: catch the error, carry on

try:
    code that might raise an error
except Exception as e:
    runs only if an error happened
try:
    v = int(input("Enter a numeric value: "))
    print("12 divided by your input value is", 12 / v)
except Exception as e:
    print("You entered an invalid value.")
    print(e)

print("Done")   # reached either way

Three runs

User typesPrints
412 divided by your input value is 3.0 Done
0You entered an invalid value. division by zero Done
abcYou entered an invalid value. invalid literal for int() with base 10: 'abc' Done

As soon as a line in try raises, Python jumps to except; the rest of try is skipped.

Remember: Put only the risky lines in try; except is the plan B; the program continues after both.

More detail

except: with nothing after it also catches everything, but it gives you no details and even catches Ctrl+C. except Exception as e: is better: e holds the exception, and print(e) shows its message.

Catching an exception is also called handling it. The aim is to fail gracefully, for example by asking again, instead of letting the program crash.

Source: Lecture 6, “Handling an exception”, “Using except with or without the generic exception”.

Part 6 · Handle

Catch specific exceptions, generic last

Right

Specific first, generic last

try:
    myList = ["Red", "Green", "Blue"]
    v = int(input("Enter a numeric value: "))
    print("12 divided by your input value is", 12 / v)
    print(myList[v])
except ZeroDivisionError:
    print("You entered a 0. Cannot divide by 0.")
except ValueError:
    print("You entered a non-numeric value.")
except Exception as e:
    print("An exception occurred.", e)

Each except names the error it handles. Python tries them top to bottom and runs only the first that matches.

Wrong

Generic first hides the rest

try:
    ...
except Exception as e:      # catches everything…
    ...
except ZeroDivisionError:   # …so this never runs
    ...

Unmatched errors

An error that matches no except is not handled: with only except ValueError, typing 0 still crashes with ZeroDivisionError.

Remember: Most specific except first, except Exception last, because the first match wins.

More detail

In the right-hand example, typing 5 gets past the division (12 / 5) but then myList[5] raises IndexError, which only the generic handler catches: “An exception occurred. list index out of range”.

Catch what you expect and know how to handle. Catching everything can hide real bugs.

One except can name several types in a tuple: except (ValueError, ZeroDivisionError) as e:.

Source: Lecture 6, “Using specific exceptions”, “Handling several types of exceptions”, “Difference between generic and specific exceptions”.

else and finally

try:
    try block
except SpecificExceptionA:
    handler A
except Exception:
    generic handler
else:
    runs only if no exception
finally:
    runs always: clean-up
a, b = 10, 0
try:
    result = a / b
    print(f"The result is {result}")
except ZeroDivisionError:
    print("Error: Division by zero is not allowed.")
else:
    print("Thank you. Bye!")
finally:
    print("Execution of the try block is complete.")
Error: Division by zero is not allowed.
Execution of the try block is complete.

With b = 5: “The result is 2.0”, “Thank you. Bye!”, then the finally line.

BlockRuns when
tryalways, until a line raises
excepta matching exception was raised
elsethe try block finished with no exception
finallyalways, error or not: closing files, connections

Remember: else = it worked; finally = no matter what.

More detail

Code in else and finally can raise exceptions too, and those aren't caught by the except blocks above them, so be careful what you put there.

try, except, else and finally don't create a new scope: a variable set in try is visible after the whole statement, but one set in except exists only if that except ran.

Why use else rather than putting the code at the end of try? So that errors from that code aren't accidentally caught by the except meant for the risky line.

Source: Lecture 6, “The else keyword”, “The finally keyword”, “Unified try/except/else/finally”.

Files: open, use, close

The old way

1 Open the file

2 Read, write or append

3 Close it

Files persist: the data stays on disk after the program ends.

file = open('example.txt', 'r')
content = file.read()
file.close()          # easy to forget!

Best practice: with

with open('example.txt', 'r') as file:
    content = file.read()
# closed automatically here, even after an error

with closes the file for you when the block ends. Always prefer it.

print(file.name, file.mode, file.closed)

A file object knows its name, its mode, and whether it's closed.

Remember: Open with with, and the file closes itself.

More detail

Why closing matters: changes may not be written to disk until the file is closed; every open file uses memory; and the operating system limits how many files one program can have open (often 1024). Hit that limit and open fails with OSError: [Errno 24] Too many open files.

open(name, mode) takes the file name (a path, relative to the folder the program runs in) and an optional mode, 'r' by default. A missing file in read mode raises FileNotFoundError.

Source: Lecture 6, “Why use files?”, “open() method”, “Opening Files”, “File attributes”, “close() method”.

Access modes

ModeRead?Write?If the file existsIf it doesn't
'r' (default)yesnoread from the startFileNotFoundError
'w'noyeserased firstcreated
'a'noyesnew text added at the endcreated
'r+'yesyeskept; read and write from the startFileNotFoundError
'w+'yesyeserased firstcreated
'a+'yesyeskept; writes go at the endcreated

Binary

Add **b** for binary files: 'rb', 'wb', 'ab', 'rb+', 'wb+', 'ab+'.

r+ versus w+

'r+' keeps the contents; 'w+' wipes them. Both let you read and write.

Remember: w wipes, a adds, r reads. Add + to do both, b for bytes.

More detail

'w' erasing the file is the classic data-loss bug: opening your only copy of some data in 'w' mode to “update” it deletes everything before you've written a byte. Use 'a' to add, or read everything first.

open also takes optional buffering and encoding arguments. For text files, encoding="utf-8" avoids surprises with accented characters on Windows.

Source: Lecture 6, “File access modes”, “Difference between r+ and w+”.

Four ways to read a file

with open("mydata.txt", "r") as f:
    for line in f:          # the iterator: best for big files
        print(line.strip())
This is my FIRST line.
This is my SECOND line.
This is my THIRD line.

Without .strip(), each line's own \n plus print's new line gives a blank line between lines.

Which one?

MethodGivesMemory
f.read()the whole file as one stringhigh: all of it
f.readline()the next line ('' at the end)low, but you loop by hand
f.readlines()a list of every linehigh: all of it
for line in f:one line per looplow: one line at a time

readline() needs its own loop:

with open("example.txt", "r") as file:
    line = file.readline()
    while line:                 # "" (end of file) is False
        print(line.strip())
        line = file.readline()

Remember: For line-by-line work, loop over the file: for line in f:. It's short, fast and uses little memory.

More detail

read() and readlines() suit small files, or when you need all the lines at once (to sort them, or jump to line 500). On a huge file they can run out of memory.

readline() gives you precise control, such as reading a header line before the loop, but it's longer and slightly slower than the iterator.

Each line keeps its newline character \n at the end. line.strip() removes it (and any other surrounding spaces); line.rstrip("\n") removes only the newline.

Source: Lecture 6, “Reading Files”: read(), readline(), readlines(), iterator approach.

Writing and appending

write()

with open('output.txt', 'w') as file:
    file.write('This is line 1\n')
    file.write('This is line 2\n')

You add the \n yourself. Good for strings you build as you go.

writelines()

lines = ['Line 1\n', 'Line 2\n', 'Line 3\n']
with open('output.txt', 'w') as file:
    file.writelines(lines)

A list of ready-made lines in one call. Fastest for lots of data.

print(file=)

with open('output.txt', 'w') as file:
    print('This goes to the file', file=file)
    print('So does this!', file=file)

Adds the new line for you, and sep/end work as usual.

Appending

with open("output.txt", "a") as file:     # "a": keep what's there
    file.write("New content\n")

'w' replaces the file's contents; 'a' adds to the end.

Remember: write needs your own \n; writelines doesn't add any; print(…, file=f) does it for you.

More detail

Despite its name, writelines doesn't add newlines between items: each string in the list must already end with \n.

write only accepts strings. Convert numbers first: file.write(str(total) + "\n"), or use an f-string.

Source: Lecture 6, “Writing Files”, “Appending to Files”.

Text files and binary files

Two kinds of file

Text filesBinary files
html, XML, CSS, JSONpdf, doc, xls
py, c, javapng, jpg, gif
txt, tex, RTFmp4, mkv, mp3, wav
csv, tsvsqlite, mdb
ini, cfgzip, exe, dll

Both are just 0s and 1s on disk. A text file is decoded into characters with an encoding such as UTF-8; a binary file is read as raw bytes.

Writing and reading bytes

with open("mybin_file.bin", "wb") as f:
    f.write(bytearray([3, 15, 21, 37, 45]))

with open("mybin_file.bin", "ab") as f:
    f.write(bytearray([100, 100, 100]))

with open("mybin_file.bin", "rb") as f:
    print(list(f.read()))
[3, 15, 21, 37, 45, 100, 100, 100]

bytearray turns a list of numbers from 0 to 255 into bytes.

Remember: Text mode gives you strings; binary mode ('b') gives you bytes, numbers from 0 to 255.

More detail

bytearray([300]) raises ValueError: byte must be in range(0, 256): one byte holds 8 bits.

f.read() in binary mode returns a bytes object; list() turns it into a list of integers so you can see the values.

Source: Lecture 6, “File types”, “Writing to binary files”, “Reading a binary file”, “Appending to a binary file”.
