Part 7 · Objects

From machine code to objects

Machine code · 1st generation: binary fed straight to the CPU

Assembly · 2nd generation: mnemonics like addi, jal; fast but tied to one processor

High-level · C, Java, Python: close to human language, translated by a compiler or interpreter

Object-oriented · data and code bundled into objects

Low level

fibonacci:
    addi $sp, $sp, -12
    sw   $ra, 8($sp)
    ...
    jal  fibonacci
    add  $v0, $s1, $v0

Part of a Fibonacci function in MIPS assembly: register by register.

Object-oriented programming

WhenMilestone
1965Simula: the first object-oriented language
1970sSmalltalk develops the ideas
early 1980sStroustrup adds objects to C: C++, the first widely used OO language
early 1990sGosling's team at Sun designs Java
todaymost languages, Python included, support OOP

Remember: Each generation hides more of the machine. Objects hide the details behind a name and a set of actions.

More detail

Assembly is still used where every cycle counts, such as embedded systems and time-critical code, because it can exploit one processor's architecture exactly. The price is portability: the code only runs on that processor. You'll write MIPS assembly in the Architecture module.

OOP aims at better program design and better modularisation: code organised around the things in the problem (students, robots, cups) is easier to reuse and to change.

Source: Lecture 7, “Evolution of programming languages”, “Object-oriented programming paradigm”.

Classes and objects

Blueprint and house

A class is a blueprint; an object is a house built from it. One blueprint, many houses.

ClassObject
Isthe planthe thing built from the plan
How manyoneas many as you like
ExampleHouseh1, h2
class House:
    pass            # empty for now

h1 = House()        # make an object (an instance)
h2 = House()        # another, separate one

An object has

  • Attributes: the data an object holds (variables)
  • Behaviour: what it can do (methods)

Remember: Class = blueprint, object = the house. Calling the class, House(), builds a new object.

More detail

“h1 is an instance of class House” and “h1 is an object of type House” mean the same thing. type(h1) shows <class '__main__.House'>.

Class names use CapitalisedWords (House, UniversityMember), unlike the snake_case of variables and functions.

Source: Lecture 7, “Class”, “Simplest class possible”, “Object”, “Creating an instance of a class”.

Part 7 · Objects

Methods, self and __init__

class Person:
    def __init__(self, name):
        self.name = name          # store it on this object

    def say_hi(self):
        print('Hello, my name is', self.name)

p = Person("Adam")
p.say_hi()
Hello, my name is Adam

self

A method is a function defined inside a class. Its first parameter, self, is the object the method was called on: p.say_hi() runs say_hi with self = p.

__init__

__init__ runs automatically as soon as an object is created. Use it to give the new object its starting values. Person("Adam") passes "Adam" to name.

Remember: self is “this object”. __init__ sets up each new object; self.x = … gives it an attribute.

More detail

You never pass self yourself: Python fills it in. That's why say_hi(self) is called as p.say_hi() with no arguments.

self is only a convention, but every Python programmer expects it, so don't rename it.

Names with two underscores on both sides (__init__, __str__, __len__) are special methods that Python calls for you at particular moments.

Source: Lecture 7, “Methods”, “The self parameter”, “The __init__ method”.

Class variables and object variables

class Robot:
    population = 0                     # class variable: one shared copy

    def __init__(self, name):
        self.name = name               # object variable: one per robot
        print("(Initializing {})".format(self.name))
        Robot.population += 1

    def die(self):
        print("{} is being destroyed!".format(self.name))
        Robot.population -= 1

    @classmethod
    def how_many(cls):
        print("We have {:d} robots.".format(cls.population))
droid1 = Robot("Alpha5")
droid2 = Robot("HK-47")
Robot.how_many()
droid1.die()
Robot.how_many()
(Initializing Alpha5)
(Initializing HK-47)
We have 2 robots.
Alpha5 is being destroyed!
We have 1 robots.
WhereCopies
populationin the class bodyone, shared by all
self.nameset on selfone per object

Remember: Class variable: one copy shared by every object. Object variable (self.x): each object has its own.

More detail

Robot.population += 1 changes the single shared counter, so every robot sees the new value. If you wrote self.population += 1 instead, Python would create a separate object variable on that one robot and the shared count would never change.

The lecture's full die method also prints “There are still 1 robots working.” or, for the last robot, “HK-47 was the last one.”, using {:d} in .format() to insert a whole number.

Source: Lecture 7, “Class and object variables”.

Part 7 · Objects

Instance, class and static methods

Instance method

def getYear(self):
    return self.year

Needs an object; reaches it through self.

Class method

@classmethod
def from_string(cls, s):
    day, month, year = map(int, s.split('-'))
    return cls(day, month, year)

Belongs to the class; gets the class as cls. Often a factory that builds objects.

Static method

@staticmethod
def is_date_valid(s):
    day, month, year = map(int, s.split('-'))
    return day <= 31 and month <= 12

Gets neither self nor cls: a plain utility function kept in the class.

myDate = Date.from_string('19-11-2030')
print(myDate.getYear())
print(Date.is_date_valid('5-4-2030'))
2030
True

Remember: self → instance method, cls + @classmethod → class method, neither + @staticmethod → static method.

More detail

The lecture's CookieCake class uses a static method circle_area(r) that returns r ** 2 * math.pi. It can be called on the class, CookieCake.circle_area(10) → 314.159…, or used inside other methods.

map(int, "19-11-2030".split("-")) applies int to each piece, turning ['19', '11', '2030'] into the numbers 19, 11 and 2030. map returns a lazy map object; wrap it in list() to see the values: list(map(len, ('January', 'February', 'March'))) → [7, 8, 5].

Lines starting with @ are decorators: they change how the function below them behaves.

Source: Lecture 7, “Class and object methods”, “Static methods”, “Summary”.

Public, protected and private

class Cup:
    def __init__(self):
        self.color = None       # public
        self._content = None    # protected
        self.__shape = "round"  # private

redCup = Cup()
redCup.color = "red"           # fine
print(redCup.__shape)          # error
AttributeError: 'Cup' object has no attribute '__shape'

Conventions, not locks

WrittenMeaning
namepublic: use from anywhere (the default)
_nameprotected: “internal, please don't touch”
__nameprivate: renamed to hide it

Python doesn't enforce any of this. redCup._Cup__shape still reaches the private value.

Remember: One underscore says “don't touch”; two underscores hide the name. In Python privacy is a convention, not force.

More detail

Two leading underscores trigger name mangling: inside class Cup, __shape is stored as _Cup__shape. Its purpose is to stop subclasses accidentally overwriting the parent's private attributes, not to keep determined code out.

Names with two underscores at both ends, like __init__, are special methods, not private ones.

Source: Lecture 7, “Access control to class variables and methods”, “Private variables and methods”.

Inheritance: build a class on top of another

The child (subclass) inherits every attribute and method of its parent (superclass), then adds or changes what it needs.

class UniversityMember:
    def __init__(self, name, age):
        self.name = name
        self.age = age

class Student(UniversityMember):           # parent in brackets
    def __init__(self, name, age, grade):
        UniversityMember.__init__(self, name, age)  # parent part
        self.grade = grade

class AdminStaff(UniversityMember, Employee):  # two parents
    ...

Remember: class Child(Parent): inherits everything. If the child has its own __init__, call the parent's yourself.

More detail

Python only calls the parent's __init__ automatically when the child doesn't define its own. Student defines one, so it must call UniversityMember.__init__(self, name, age) (or the shorter super().__init__(name, age)), otherwise name and age are never set.

Listing more than one parent, as AdminStaff does, is multiple inheritance. The lecture's diagram of types of inheritance shows single (one parent), multiple (several parents), multilevel (a chain: grandparent → parent → child), hierarchical (several children of one parent) and hybrid (a mix).

isinstance(s, UniversityMember) is True for a Student: a child object counts as its parent type too.

Source: Lecture 7, “Inheritance”, “Inheritance in action”, “Types of inheritance”.

Overriding methods

Same name, new behaviour

class BaseClass:
    def __init__(self):
        self.value = 4
    def get_value(self):           # overridden
        return self.value

class Subclass(BaseClass):
    def get_value(self):           # overriding
        return self.value * 2

print(Subclass().get_value())
8

Define a method with the same name in the child, and it replaces the parent's for child objects.

Extend, don't repeat

def tell(self):                    # in Student
    UniversityMember.tell(self)    # reuse the parent's part
    print('Grade: "{:d}"'.format(self.grade))

Student('Lena', 21, 75).tell()
Name:"Lena" Age:"21" Grade: "75"

An override can still call the parent's version and add to it.

Look in the object's own class

Then its parents, in the order listed

Finally object, the root of every class

Remember: Python looks for a method in the child first, then the parents in order: the closest definition wins.

More detail

Subclass has no __init__, so Python uses BaseClass.__init__ and value is 4; get_value is overridden, so the result is 8.

Every class ultimately inherits from object, which is where default behaviour such as printing <__main__.Robot object at 0x…> comes from. Student.__mro__ shows the full lookup order: Student, UniversityMember, object.

Source: Lecture 7, “Method overriding”, “The Object class”.
