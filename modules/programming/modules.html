Part 8 · Import

Modules: code in another file

The module

support.py

# support.py
myString = "it is Monday!"
myList = [10, 20, 30]

def myFunc(name):
    print("Hello", name)

class someClass:
    pass

The program

usemodule.py

# usemodule.py, in the same folder
import support

print(support.myString)
print(support.myList)
support.myFunc("Lisa")
o = support.someClass()
it is Monday!
[10, 20, 30]
Hello Lisa

Remember: A module is just a .py file. import name (no .py) runs it once and gives you its contents as name.thing.

More detail

A module groups related functions, classes and variables so several programs can share them. Every .py file you write is already a module.

Run module examples as normal .py files in an editor such as PyCharm rather than in Jupyter, so Python finds support.py in the same folder.

A module's code runs the first time it's imported; importing it again in the same program reuses the already-loaded module.

Source: Lecture 8, “Modules”, “Importing and using a module”.

Part 8 · Import

Four ways to import

WriteThen useNote
import supportsupport.myStringsafest: every name keeps its module prefix
from support import myString, myListmyStringshorter, but may clash with your own names
from support import myString as ssrename to avoid a clash, or to shorten
from support import *myString, myList, …not recommended: imports everything blindly

Examples

import math
print(math.sqrt(81))

from math import sqrt
print(sqrt(81))

import numpy as np     # a common shorthand

Why not *

from module import * can silently replace names you already have, such as your own myList, and makes it hard to tell where a name came from.

Remember: import m → write m.x; from m import x → write x; as renames; avoid *.

More detail

import module as alias also works for whole modules; import numpy as np and import pandas as pd are conventions you'll meet in Part 9.

Source: Lecture 8, “The import statement”.

Part 8 · Import

Where Python looks for a module

1 The folder of the program being run

2 Each folder in the PYTHONPATH environment variable, if set

3 The folders set up when Python was installed (standard library, installed packages)

import sys

for path in sys.path:
    print(path)

The first match wins

The final search list is sys.path. Python takes the first match, so a file of your own called random.py or math.py will hide the real module.

Remember: Python searches the program's own folder first: never name your files after standard modules.

More detail

If an import fails with ModuleNotFoundError, check the module is in the program's folder or installed for the same Python you're running (pip install puts packages in step 3's folders).

sys.path is an ordinary list, so a program can add a folder to it before importing.

Source: Lecture 8, “Module search order”.

Part 8 · Import

if __name__ == "__main__":

A module that can also run

# mymathutils.py
def squareit(n):
    return n * n

def cubeit(n):
    return n * n * n

def main():
    anum = int(input("Please enter a number: "))
    print(squareit(anum))
    print(cubeit(anum))

if __name__ == "__main__":
    main()

Imported

# usemymathutils.py
import mymathutils

x = mymathutils.squareit(10)
print(x)
100

No number is asked for: main() didn't run, because the module was imported.

Why it works

How the file runs__name__ ismain() runs?
run directly"__main__"yes
imported"mymathutils"no

Remember: __name__ is "__main__" only in the file you ran. Put code that should run only then under the guard.

More detail

This lets one file be both a library (other programs import its functions) and a program (run it to try them, often as a test).

Without the guard, importing mymathutils would immediately ask the user for a number, which the importing program almost certainly doesn't want.

Source: Lecture 8, “if __name__ == "__main__":”.

The standard library: math, random, datetime, os

math

import math
print(math.pi)
print(math.sqrt(81))
print(math.pow(2, 3))
print(math.factorial(5))
print(math.sin(1.57))   # radians
3.141592653589793
9.0
8.0
120
0.9999996829318346

random

import random
print(random.choice(['iron', 'silver', 'gold']))
print(random.randrange(7))   # 0 to 6

Different every run.

datetime

import datetime
now = datetime.datetime.today()
print(now.year, now.month, now.day)
dto = datetime.datetime(2031, 5, 17, 12, 30, 25)
print(dto)
2026 11 1
2031-05-17 12:30:25

os

import os
print(os.getcwd())          # current folder
print(os.listdir('.'))      # its contents
print(os.uname())           # macOS / Linux only

Remember: Before writing it yourself, check the standard library: maths, randomness, dates and files are all there.

More detail

math.pow always returns a float (8.0), while 2 ** 3 gives the int 8. Trigonometric functions take radians: degrees × π / 180.

os.uname() doesn't exist on Windows; use platform.system() or platform.uname() from the platform module instead, which work everywhere.

Full documentation for each module is at docs.python.org/3/library/ (math, random, datetime, os).

Source: Lecture 8, “Python standard modules”: math, random, datetime, os.

Part 8 · Import

Packages: folders of modules

pkg0/
├── __init__.py
├── mod0.py
└── pkg1/
    ├── __init__.py
    ├── mod1.py      # defines foo()
    └── mod2.py      # defines someClass

A package is a folder of modules (and sub-packages). A folder needs an __init__.py file for Python to treat it as a package.

Importing from a package

import pkg0.pkg1.mod1
pkg0.pkg1.mod1.foo()

from pkg0.pkg1.mod1 import foo
foo()

from pkg0.pkg1.mod2 import someClass as Bar
b = Bar()

Dots follow the folders down to the module.

Remember: Package = folder with __init__.py; dots in an import follow the folder path.

More detail

Packages give modules a hierarchy and prevent name collisions: two packages can each have a module called utils without clashing.

__init__.py can be empty; it can also run set-up code or choose what from package import * exposes. Without it, Python won't look for submodules inside the folder in the classic way the lecture describes.

Further reading from the lecture: the Python tutorial on modules, and Nick Coghlan's “Traps for the Unwary in Python's Import System”.

Source: Lecture 8, “Packages”, “The __init__.py”.

Part 8 · Import

Logging: a record of what happened

Maintenance is the most expensive phase of software. Logging records events while the program runs, so you can see what it did, and when, after the fact.

import logging

logging.debug("This is a debug message")
logging.info("This is an info message")
logging.warning("This is a warning message")
logging.error("This is an error message")
logging.critical("This is a critical message")
WARNING:root:This is a warning message
ERROR:root:This is an error message
CRITICAL:root:This is a critical message

Severity levels

LevelValueFor
DEBUG10detailed diagnosis
INFO20things working as expected
WARNING30something unexpected; default
ERROR40a function failed
CRITICAL50the program may not continue

Only messages at or above the set level are shown.

Remember: Logging shows messages at the set level and above; the default level is WARNING, so debug and info stay hidden.

More detail

root in the output is the name of the default logger. Libraries use the same logging module, so their messages and yours can end up in one consistent log.

Unlike print, logging can be switched to a quieter level or redirected to a file without changing every line that logs.

Source: Lecture 8, “Logging”, “Logging levels”.

Part 8 · Import

Configuring logging with basicConfig

import logging

logging.basicConfig(level=logging.DEBUG,
                    filename='output.log',
                    filemode='w',
                    format='%(module)s - %(levelname)s - %(message)s')

logging.warning("This is a warning message")

In output.log

loggingFormatExample - WARNING - This is a warning message

The options

ParameterSets
levelthe lowest severity shown
filenamea file to log to
filemode'a' (append, default) or 'w'
formatthe layout of each line
In formatInserts
%(asctime)stime of the event
%(levelname)sWARNING, ERROR…
%(message)sthe message
%(module)smodule name
%(funcName)sfunction name
%(levelno)d10, 20, 30…

Remember: Call basicConfig once, before the first log message, to set the level, the file and the format.

More detail

basicConfig only takes effect the first time logging is configured. In Jupyter, after any earlier logging call it does nothing; restart the kernel or run the example as a .py file.

Why is it basicConfig and not basic_config, as PEP 8 recommends for function names? The module was adapted from a Java logging library, and Java uses camelCase. By the time it joined the standard library, too much code used the name to change it. PEP 8 allows mixedCase “where that's already the prevailing style … to retain backwards compatibility”.

The full list of format attributes is under “LogRecord attributes” in the logging documentation.

Source: Lecture 8, “Customising the logging level”, “basicConfig() parameters”, “A historical note”.
