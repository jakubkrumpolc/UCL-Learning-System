Part 12 · Markup

Labels on the data, not a schema beside it

Two kinds of structure

Relational data is regular. The columns are known in advance, they rarely change, and every row of a table has them. Semi-structured data has a shape, but the shape can be irregular, incomplete, or different from one item to the next. The data describes itself.

OEM, the early model

The Object Exchange Model is a tree. Each node has a label, an id, and sometimes a value. One name might be a single string. The next might be split into first and last. One rent is monthly, the next annual.

You reach a node by its id or by the path of labels down the tree. A DataGuide summarises which paths exist, so a query can fail fast when a path is impossible.

Remember: Semi-structured data is a tree of labels. The shape can differ from one item to the next, and queries follow paths.

More detail

The lecture’s principles are short. The structure is a flexible tree. Queries are paths. Efficient queries need a summary of those paths, because there is no fixed catalogue of columns to check against.

Source: Lecture 9a, well-structured versus semi-structured data, and OEM.

Part 12 · Markup

Tags you define yourself

A document

XML is text in tags you invent. An element is an opening tag, content, and a closing tag. Order matters. An attribute is a name and value written inside the opening tag, used for description rather than for a nested value.

<STAFF branchNo="B005">
  <STAFFNO>SL21</STAFFNO>
  <SALARY>30000</SALARY>
</STAFF>

Saying what is allowed

A DTD lists the elements and how they nest. * means zero or more, + one or more, ? optional. An attribute can be an ID or an IDREF, a pointer to an ID.

XML Schema is the newer replacement. A schema document is itself XML, it has richer types, and it can say that a value is unique or a key. DTDs are the older mechanism the lecture still expects you to recognise.

Remember: XML is nested tags. Attributes sit inside the opening tag. A DTD or an XML Schema says which nestings are legal.

More detail

The lecture’s example document also names a stylesheet. That is presentation. The elements and the schema are the data. Do not treat an attribute and a child element as interchangeable in an exam answer: order of elements matters, and attributes are unordered descriptive pairs.

Source: Lecture 9a, XML, elements and attributes, DTD and XML Schema.

Part 12 · Markup

Paths, then a FLWOR expression

XPath

Steps are separated by /. @ names an attribute. Brackets filter.

doc("staff_list.xml")/STAFFLIST/STAFF[1]/STAFFNO

That opens the file, steps into STAFFLIST, takes the first STAFF, and returns its STAFFNO. //STAFF finds STAFF elements anywhere below the current node. [@branchNo="B003"] keeps elements with that attribute.

XQuery

A FLWOR expression is FOR, LET, WHERE, ORDER BY and RETURN. You need at least one FOR or LET, and a RETURN.

FOR $S IN doc("staff_list.xml")//STAFF
WHERE $S/SALARY > 15000
  AND $S/@branchNo = "B005"
RETURN $S/STAFFNO

The query engine walks an in-memory tree, the Document Object Model, rather than a set of tables.

Remember: XPath is a path with filters. XQuery adds FOR, WHERE and RETURN around those paths.

More detail

Several paths can name the same node. //STAFF[1]/STAFFNO and the fully spelled path through STAFFLIST can return the same staff number. The lecture lists them to show that the path is not unique.

Source: Lecture 9a, XPath and the FLWOR example.

Part 12 · Markup

A smaller notation, and a seat next to the tables

JSON

JSON is objects and arrays, the same idea of nesting in less text. An object is a list of names and values. An array is an ordered list. It is the usual exchange format now, and the structure can still vary from one object to the next.

XML can say more with schemas and mixed content. JSON wins when the goal is to move data cheaply.

Alongside tables

  • Use XML or JSON only as a message between databases that stay relational. That is data-centric.
  • Store a document as a CLOB or an XML type in one column.
  • Shred the tree into tables whose columns are the repeating paths.
  • Or keep a schema-independent edge table: parent, label, value.

Remember: JSON is the compact nested format. XML can be a message, a column, or a tree shredded into tables.

More detail

The lecture’s closing contrast: semi-structured data allows nested lists and missing pieces. Relational data wants rectangular tables and pays for that with simpler queries and stronger constraints.

Source: Lecture 9a, JSON, and storing XML in a relational database.
