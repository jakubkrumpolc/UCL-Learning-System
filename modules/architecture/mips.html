The instruction, as 32 bits and as a line of assembly

MIPS32 is a small load-store machine. Three layouts cover the instructions, five addressing modes say where the operand is, and MARS lets you watch a program do it.

Part 3 · MIPS

Arithmetic stays in the registers

What MIPS32 is

  • Addresses are 32 bits, and every instruction is a 32-bit word. A word occupies four consecutive bytes, so the program counter steps by 4.
  • There are 32 registers, $0 to $31. $0 is hardwired to zero.
  • It is a RISC, load-store design. Only load and store touch memory. Every other instruction reads and writes registers.

Adding two numbers that live in memory therefore takes four instructions: load, load, add, store.

MIPS32 is the 32-bit architecture this course programs. MIPS64 is the same idea at 64 bits. Chips in this family sit in consoles, routers, printers and the radiation-hardened processor that flew on New Horizons.

The three layouts

FormatUsed forFields
Rregister arithmeticop, rs, rt, rd, shamt, funct
Iimmediate, load, store, branchop, rs, rt, 16-bit immediate
Jjump, jump-and-linkop, 26-bit target

The format is how the 32 bits are sliced. It is not the same thing as an addressing mode, which is how an operand is found. That distinction gets its own section, because addi, beq and lw are all I-type and find their operands three different ways.

In MARS, instructions are placed from 0x00400000. The word at the program counter on the lecture diagram is the one about to run.

Remember: MIPS arithmetic happens in registers. Only load and store touch memory, so adding two memory words takes four instructions. $0 is always 0.

More detail

The course picks MIPS for a clean ISA: few instruction shapes, and the concepts (registers, addressing, control) show through. The same concepts exist on more complicated machines, buried under extra formats.

A useful pair that needs no memory: add $8, $0, $0 clears $8, and add $8, $1, $0 copies $1 into $8. Both are ordinary adds against the zero register.

Source: Lecture 6, “MIPS32”, “Arithmetic and Registers”, “Instruction formats”.

R-type: six fields, two registers in, one out

The fields, and the lecture’s add

FieldBitsMeaning
op60 for every R-type here
rs5first source register
rt5second source register
rd5destination register
shamt5shift amount, 0 unless it is a shift
funct6which operation
add $8, $1, $2
000000 00001 00010 01000 00000 100000
op=0  $1    $2    $8    0     funct=0x20

Subtract, and a whole expression

sub $12, $6, $3          # $12 ← $6 − $3
000000 00110 00011 01100 00000 100010
funct = 0x22

Assembly is written destination first: op rd, rs, rt. The machine word is not in that order. rs comes before rt, and rd is the fourth field.

The lecture’s expression x = a − b + c − d, with a, b, c, d already in $4, $5, $6, $7:

sub $10, $4, $5    # a - b
sub $11, $6, $7    # c - d
add $12, $10, $11  # x

Comments start with #. The three machine words on the slide are those three instructions, funct 0x22, 0x22, then 0x20.

Remember: R-type is op, rs, rt, rd, shamt, funct. op is 0 and funct picks add (0x20) or sub (0x22). The destination is written first in assembly and fourth in the word.

More detail

Five bits name a register, because 25 = 32. Six bits of funct, together with op = 0, leave room for the rest of the arithmetic and logic set.

Encode add $8, $1, $2 once from scratch: op 000000, rs 00001, rt 00010, rd 01000, shamt 00000, funct 100000. Concatenate, then group in fours if you want it in hex: 0022402016.

Source: Lecture 6, “R-Type Instruction Encoding”, the x = a − b + c − d example.

The same adder, two overflow rules, and bitwise logic

funct codes from the lecture

InstructionfunctDoes
add / addu0x20 / 0x21add, with / without a signed-overflow trap
sub / subu0x22 / 0x23subtract, with / without that trap
and, or, xor, nor0x24–0x27bitwise, including not-or
slt / sltu0x2A / 0x2Bset rd to 1 if rs < rt, signed / unsigned

The bits of an add and an addu sum are identical. Part 2 is why both exist: signed overflow is a different event from a carry out, and only the signed instructions raise it.

and, or, xor, nor, one bit at a time

ABandorxornor
000001
010110
100110
111100

and keeps a bit only where both inputs have it. That is a mask. or forces bits on. xor is 1 where the bits differ. nor is the not of or, and with $0 it is a bitwise not.

Remember: add and addu compute the same sum. add traps on signed overflow; addu does not. and, or, xor and nor act on each bit on its own.

More detail

The “u” does not mean “zero-extend” and it does not mean “a different circuit”. It means “do not signal signed overflow”. You will see the same split on addi and addiu, where the immediate is sign-extended in both.

slt is how a comparison becomes data. The following instruction is usually a branch on whether that 1 or 0 is equal to $0. There is no single instruction for ≤ or ≥ between two registers.

Source: Lecture 6, the R-type table, “add and addu”, the logic truth tables.

Part 3 · MIPS

I-type: a 16-bit immediate in the instruction

The layout

op (6)   rs (5)   rt (5)   immediate (16)

A signed immediate covers −215 to 215−1, which is −32768 to 32767. An unsigned one covers 0 to 65535. Before use, a signed immediate is sign-extended to 32 bits and an unsigned one is zero-extended.

Loads and stores use base addressing. The address is rs plus the extended immediate, and rt is the register loaded or stored.

The lecture’s load and store

lw $20, 0x1234($5)
100011 00101 10100 0001001000110100
op=0x23  $5   $20   offset 0x1234

$20 ← Memory[$5 + 0x00001234]
sw $8, 0x8000($15)
op=0x2B  $15  $8   offset 0x8000

Memory[$15 + 0xFFFF8000] ← $8

0x8000 has its top bit set, so the signed 16-bit offset extends to 0xFFFF8000, a negative displacement. The store writes $8 at that address. The load’s offset 0x1234 has its top bit clear, so it extends with zeros.

Remember: I-type is op, rs, rt, and 16 bits. lw and sw use rt as the data register and rs plus a sign-extended offset as the address. 0x8000 extends to 0xFFFF8000.

More detail

Lecture 8 writes the signed range as “−32,769 to +32,768”. That is one past each end. Sixteen-bit two’s complement, and the range Lecture 6 states, is −32768 to +32767.

Opcode 0x23 is lw and 0x2B is sw. The assembly form is lw rt, offset(rs), which is the opposite of the R-type habit of naming the destination first in a way that matches field order: here the immediate is last in both the assembly and the word.

Source: Lecture 6, “I-Type”, “Load Word”, “Store Word”; Lecture 8 on the immediate range.

Part 3 · MIPS

A branch counts instructions, and lui builds a constant

addi sign-extends, even the unsigned one

addi  $20, $5, 0xABCD
addiu $20, $5, 0xABCD

both do  $20 ← $5 + 0xFFFFABCD

0xABCD is negative as 16 bits, so both instructions sign-extend it. The difference is the trap: addi signals signed overflow, addiu does not. To put the unsigned bits 0x0000ABCD into a register, use ori with $0, which zero-extends.

A conditional branch is also I-type. The 16-bit field counts instructions, starting from the instruction after the branch.

beq $20, $5, offset
if ($20 == $5)
    PC ← PC + 4 + signExtend(offset) × 4

Any 32-bit constant is two instructions

lui $17, 0x1234     # $17 ← 0x12340000
ori $17, $17, 0x5678 # $17 ← 0x12345678

lui writes the immediate into the top half and clears the bottom half. ori then fills the bottom without disturbing the top, because those low bits were zero.

The pseudo-instruction la (load address) and li (load immediate) are the assembler writing this pair for you. They are not single machine instructions. In MARS you can expand them and watch.

Remember: A branch offset counts instructions from the next instruction. lui then ori plants any 32-bit constant. addiu sign-extends its immediate; the “u” only switches off the overflow trap.

More detail

The assembler turns a label on a beq into that offset: (label address − (PC+4)) / 4. From any instruction you can reach about 32768 instructions back or 32767 forward. Further, and you need a jump.

There is also bgez and the rest of the “compare with zero” branches. They are still I-type, and the offset is computed the same way. Lecture 8 lists beq, bne, bgez, bgtz, blez and bltz.

Source: Lecture 6, “addi and addiu”, “beq”, “lui and ori”; Lecture 8, “Branching and labels”.

Five ways to name an operand

ModeThe operand isSeen in
Immediatea constant in the instructionaddi $2, $0, 10
Registera register numberadd $8, $1, $2
Base, or displacementMemory[rs + offset]lw $20, 0x1234($5)
PC-relativePC+4, plus an instruction offsetbeq
Pseudo-directthe top 4 bits of the PC, then a 26-bit word address, then two zero bitsj

Format and mode are different questions

addi, beq and lw share the I-type slicing. Immediate addressing, PC-relative addressing and base addressing are three answers to “where is the operand?”.

A J-type instruction holds a 26-bit word address. Instruction addresses are multiples of 4, so the hardware shifts that field left by 2 (multiplies by 4) and keeps the top 4 bits of the PC. One jump instruction can land anywhere in a 256 MB region, and cannot by itself leave that region. jr, which jumps to an address sitting in a register, can.

j target
PC[27:0] ← target × 4
# the top 4 bits of the PC stay as they are

Remember: The format is how the bits are packed. The addressing mode is how the operand is found. addi, beq and lw are all I-type and use three different modes.

More detail

Lecture 8’s picture of the five modes is the one to be able to redraw: immediate and register need no memory address, base adds an offset to a register, PC-relative adds an offset to the PC, and pseudo-direct stitches the PC’s top bits onto the instruction’s target.

Because the top 4 bits come from the PC, a J-type jump that looks correct in isolation can land in the wrong 256 MB block if the PC and the target disagree in those bits. A register jump does not have that limit.

Source: Lecture 8, “MIPS Addressing Modes”, and the note that modes and formats differ; Lecture 9 for the J-type field widths.

Part 3 · MIPS

Shifts, and pulling one field out of an instruction

Three shifts

  • sll rd, rt, shamt shifts left, and brings in zeros. Left by k multiplies by 2k.
  • srl rd, rt, shamt shifts right logically, bringing in zeros. 64 shifted right by 2 is 16.
  • sra rd, rt, shamt shifts right arithmetically: the sign bit is copied. −16 shifted right by 2 is −4. Positive 48 shifted right by 2 is 12.
sll $5, $4, 3
# $4 holds 2:  ...0000 0010
# $5 becomes 16: ...0001 0000

The amount lives in the shamt field of the R-type word. That field is why it was sitting there, unused, in every add.

Which register does this store mention?

sw $8, 0x8000($15)
101011 01111 01000 1000000000000000
       └ rs = 01111 = 15, bits 25–21

The lecture isolates rs with a mask and a shift:

lui $5, 0x03E0     # mask over bits 25–21
and $6, $4, $5     # keep only those bits of the instruction
srl $6, $6, 21     # slide them down to the units place
# $6 is now 15

0x03E0 in the top half is the five bits that cover rs and nothing else. and keeps them, srl by 21 moves bit 21 down to bit 0.

Remember: A logical left shift by k multiplies by 2ᵏ and brings in zeros. An arithmetic right shift copies the sign. A mask and a shift pull one field out of a machine word.

More detail

Check the mask. lui $5, 0x03E0 builds 0000 0011 1110 0000 in the top half, which is bits 25 down to 21. and with the store word leaves 01111 sitting at those positions. Shift right 21 and the register holds 15, the register number written in 0x8000($15).

Shifting is also how the later lectures multiply an array index by 4. A word is 4 bytes, and sll by 2 is the multiply.

Source: Lecture 8, “Shift operations”, “bit manipulation example” (the sw word).

Part 3 · MIPS

Compare, then take the positive difference

Set, then branch on zero

The branches compare with zero, or compare two registers for equal and not-equal. Anything else is two steps.

slt  rd, rs, rt     # rd ← 1 if rs < rt (signed), else 0
sltu rd, rs, rt     # the same test, unsigned
slti rt, rs, value  # compare with a constant
# then beq or bne against $0

So “rs ≤ rt” is “slt the other way, then branch if that result is zero”: if rs is not greater, it is less or equal.

|A − B|, in the lecture’s program

.data
vals: .word 180, 100
      .space 4
.text
.globl main
main:
      la   $10, vals
      lw   $4, 0($10)    # A
      lw   $5, 4($10)    # B
      sub  $12, $4, $5   # A - B
      bgez $12, pos      # already ≥ 0
      sub  $12, $5, $4   # otherwise B - A
pos:  sw   $12, 8($10)
      li   $v0, 10
      syscall

With 180 and 100, $12 becomes 80, bgez fires, and 80 is stored at vals+8. Swap the two words and the branch falls through, so the second subtract repairs the sign. This is the Little Man’s absolute value, written with MIPS names.

Remember: slt writes 1 or 0. A branch then tests that against zero. |A−B| is subtract, branch if it is already positive, otherwise subtract the other way.

More detail

li $v0, 10 followed by syscall is how a MARS program exits. System calls are the subject of Part 4; this one is worth recognising now because every lecture program ends with it.

Single-step this in MARS with the data words swapped. The branch is one instruction, so you can see the PC either land on pos or on the second sub. That is PC-relative addressing with a label doing the arithmetic for you.

Source: Lecture 8, “set on less than”, “absolute difference version 1”.

Where the assembler puts a program

Directives and labels

A directive starts with a dot and talks to the assembler, not to the processor.

DirectiveEffect
.data / .textWhat follows goes in the data segment or the code segment
.globl mainmain is visible to the loader, so the program can be started
.word 4, 5, 8, 0Four 32-bit words
.half, .byte16-bit or 8-bit cells
.floatIEEE single-precision numbers
.asciiz "hi"Characters, then a zero byte
.space 100100 bytes, uninitialised

A label ending in a colon is a name for the next address. You rarely know the number. The assembler does, and it patches la and the branches.

The MARS map, and the first calculator

RegionStarts
Reserved0x00000000
Text (code)0x00400000
Global data, then dynamic data0x10000000, your .data from 0x10010000
Stack, growing downtoward lower addresses, from 0x7FFFFFFC
Kernel reserved0x80000000
.data
vals: .word 4, 5, 8, 0
.text
.globl main
main:
      la  $4, vals
      add $8, $0, $0
      lw  $9, 0($4)
      add $8, $8, $9
      lw  $9, 4($4)
      add $8, $8, $9
      lw  $9, 8($4)
      add $8, $8, $9
      sw  $8, 12($4)   # 4+5+8 = 17, in the fourth word
      li  $v0, 10
      syscall

Remember: .data and .text choose the segment. A label is a name for an address. In MARS, code starts at 0x00400000 and your words start at 0x10010000.

More detail

MARS is the simulator the lectures use: an editor, a memory view, breakpoints, and single-step. The course page points at the Missouri State MARS site, and Patterson and Hennessy’s Appendix A is the instruction reference (linked from Moodle).

Loads of sizes other than a word: lb/lbu, lh/lhu, and the matching stores sb, sh. The unsigned forms zero-extend into the 32-bit register. The signed forms sign-extend. That is Part 2’s widening rule, as an instruction.

Source: Lecture 7, directives, labels, memory layout, calculator 0.0; Lecture 6 for the same program’s first appearance.
