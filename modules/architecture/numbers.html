Part 2 · Numbers

Binary, hex, and the meaning of a negative bit

Every value in the machine is a fixed row of bits. The same row can be a character, an unsigned count, or a two’s-complement integer, and the hardware adds them all the same way.

Sections 9–16 · Lectures 4–5

Part 2 covers Lectures 4 and 5: converting between decimal, binary and hexadecimal, the column rules for add and subtract, two’s complement, fixed widths, the difference between carry and signed overflow, byte order, and sign extension versus zero extension.

Part 2 · Numbers

A digit times a power of the base

One rule, three bases

A number is a sum of digit × baseplace. The rightmost place is base0. Multiplying by the base is writing a 0 on the right.

ExampleAs a sumDecimal
2071102×103 + 0×102 + 7×101 + 1×1002071
110121×8 + 1×4 + 0×2 + 1×113
7D1167×256 + 13×16 + 12001

Decimal to binary by halving

Divide by 2 and keep the remainders. Read the remainders upwards.

42 ÷ 2 = 21 rem 0
21 ÷ 2 = 10 rem 1
10 ÷ 2 =  5 rem 0
 5 ÷ 2 =  2 rem 1
 2 ÷ 2 =  1 rem 0
 1 ÷ 2 =  0 rem 1

42₁₀ = 101010₂

Check: 32 + 8 + 2 = 42. Hex works the same with divisor 16. 42 ÷ 16 = 2 remainder 10, and 10 is the digit A, so 4210 = 2A16.

BAD16 = 11×256 + 10×16 + 13 = 298910. The lecture asks for this one.

Remember: A number is digits times powers of the base. Multiply by the base by writing a 0 on the right.

More detail

Binary uses digits 0 and 1. Hex uses 0–9 and then A=10, B=11, C=12, D=13, E=14, F=15. The lecture writes a base as a subscript, and often writes hex with a leading 0x, as in 0x5FAB1034.

10101112 is the lecture’s “work this one” pattern: 64 + 16 + 4 + 2 + 1 = 8710. The longer place-value example 1011001012 is 256 + 64 + 32 + 4 + 1 = 35710.

Source: Lecture 4, “Base 10”, “Binary System”, “Hexadecimal System”.

Hex is binary, in groups of four

Why anyone writes hex

A 32-bit word is miserable to copy by hand. Hex compresses it 4-to-1, because 24 = 16: each hex digit is exactly one of the 16 possible nibbles.

BinaryHexBinaryHex
0000010008
0001110019
001021010A
001131011B
010041100C
010151101D
011061110E
011171111F

Group from the right

0010 1011 1110 1011 1010 1101 0010 0001
  2    B    E    B    A    D    2    1

= 2BEBAD21₁₆

Start at the least significant bit, the right-hand end. If the length is not a multiple of 4, pad with zeros on the left before you group. Those leading zeros do not change the value, and they complete the first hex digit.

The same grouping works for a negative two’s-complement word. You do not re-negate when you switch between binary and hex; you only regroup bits.

Remember: Four bits are one hex digit. Group from the right, and pad the left with zeros if you must.

More detail

The lecture’s 32-bit example is 001010111110101110101101001000012 = 2BEBAD2116. Computers do not need this shorthand. People do, for instructions, addresses and colours.

A decimal rendering is the right one when the number means a decimal quantity, such as a salary. It is a poor one for an instruction word, whose fields sit on bit boundaries that hex still shows.

Source: Lecture 4, “Hexadecimal – shorthand for a binary number”, and the questions at the end of the lecture.

Part 2 · Numbers

Kilo sometimes means 1024

Two meanings, and the formal names

SpokenOften meansFormal name for the power of two
kilobyte, KB1024 bytes in memorykibibyte, KiB = 210
megabyte, MB1024 KBmebibyte, MiB = 220
gigabyte, GB1024 MBgibibyte, GiB = 230
terabyte and onthe next powertebi 240, pebi 250, exbi 260

Which one a sentence means

  • A bit is one 0 or 1. A lower-case b counts bits.
  • A byte is 8 bits. An upper-case B counts bytes.
  • Memory sizes are almost always the power-of-two version. 1 KB of RAM is 1024 bytes.
  • Communications are almost always decimal. 512 Kbps is 512,000 bits per second.
  • 1 MFLOP in the lecture is 1,000,000 floating-point operations per second.

Remember: In memory, kilo usually means 1024. On a wire, kilo means 1000. The formal name for 1024 bytes is a kibibyte.

More detail

The clash is with SI prefixes, where kilo is exactly 1000. Both habits are still everywhere, so the surrounding noun is the clue: RAM versus a network rate.

Lecture 12 repeats the power-of-two table for storage (KB through PB) and makes the same warning: disk makers often use the decimal million and billion, while networking quotes bits.

Source: Lecture 4, “Talking binary”, “kibibyte”; Lecture 12, “Storage Definitions”.

Part 2 · Numbers

Add a column, in whatever base

The rule

Label the digits of the two numbers ri and si, and the carry into the column ci. Then

rᵢ + sᵢ + cᵢ  =  cᵢ₊₁ × base  +  tᵢ

ti is the digit you write. ci+1 is the carry you take to the next column. The carry into the units column is 0.

Binary is the small case. 1+1+0 writes 0 and carries 1. 1+1+1 writes 1 and carries 1. Subtraction is the same idea with a borrow: ri − si − bi = ti − bi+1×base.

The lecture’s hex sum

   A B C₁₆
+  3 4 7₁₆
---------
   E 0 3₁₆
  • C+7 = 12+7 = 19 = 1×16 + 3. Write 3, carry 1.
  • B+4+1 = 11+4+1 = 16 = 1×16 + 0. Write 0, carry 1.
  • A+3+1 = 10+3+1 = 14. Write E.

Do it again in binary and regroup: you get the same hex digits. The lecture’s check is exactly that round trip. The binary column rule on the slide is the same equation with base 2, and 01012 + 11112 = 101002.

Remember: Each column: add the digits and the carry, divide by the base, write the remainder, carry the quotient.

More detail

Hex subtraction on the slide: E4516 − 27316 = BD216. Units 5−3 = 2. The sixteens column 4−7 borrows, so the digit is 13, which is D, and the sixteens-of-sixteens column pays that borrow: 14−2−1 = 11, which is B.

A base-X complement, later, is “replace each digit d by (X−1−d), then add 1”. For decimal that is nines then plus one. For hex it is F minus each digit, then plus one. For binary it is flipping bits, then plus one: two’s complement.

Source: Lecture 4, addition and subtraction in decimal, binary and hex.

Part 2 · Numbers

Negative numbers, without a minus sign

Sign and magnitude wastes a pattern

A register has only 0s and 1s, so a leading “minus” has to be a bit. Using the top bit as a sign, and the rest as a magnitude, looks familiar and works badly.

  • The range is about half what n bits could hold, and zero has two spellings: +0 and −0.
  • Adding +53 and −53 does not fall out of the ordinary adder as zero.

The Little Man simulator can print a sign. The hardware in this course does not. It uses two’s complement.

Flip the bits, then add 1

4-bit +2  = 0010
flip       = 1101
add 1      = 1110   which is −2

4-bit 1001
flip       = 0110
add 1      = 0111 = 7
so 1001 is −7

To read a negative word: flip, add 1, and put the minus back. The top bit is still a sign bit (1 means negative), but the other bits are not a plain magnitude.

What you gain: the same adder does subtraction, by adding the negation. Zero is only 000…0. In four bits, flipping 0000 gives 1111, plus 1 gives 1 0000, and the extra 1 falls off the end.

Remember: To negate: flip every bit, then add 1. Subtraction is adding that negation. Zero is all zeros, once.

More detail

The carry out of an n-bit two’s-complement addition is discarded. That discarded bit is exactly why 0000 plus its own negation comes back to 0000.

The same “complement then add 1” story works in other bases. Decimal uses 9−d. Hex uses F−d, so the 16’s complement of 5FAB103416 is A054EFCC16. A negative two’s-complement word converts to hex by grouping bits, not by taking a fresh complement.

Widening an 8-bit negative value to 32 bits is not “pad with zeros”. That would change the sign. Copy the top bit into the new positions. That is sign extension, in the next sections.

Source: Lecture 4, “Negative numbers”, “two’s complement”, “X’s complement”.

Part 2 · Numbers

A fixed number of bits

2ⁿ patterns, and no label on them

An n-bit word can represent 2n different things. Eight bits can be 256 colours, or a number, or a character. Nothing in the bits says which. The instruction that uses them decides.

The lecture’s 16-bit example 01000010010001012 is the integer 16965, and it is also the two ASCII bytes for B and E. Both readings are the bits.

WidthUnsignedSigned (two’s complement)
80 … 255−128 … 127
n0 … 2n−1−2n−1 … 2n−1−1

What 11111111 is

As an unsigned byte it is 255. As a signed byte it is −1. Both are right. The lecture’s vote is that question.

Signed bytes run from 00000000 to 01111111 (0 to 127, top bit 0) and from 11111111 down to 10000000 (−1 down to −128, top bit 1).

If a machine has 35 instructions, 5 bits are not enough (25 = 32) and 6 bits are (26 = 64). Encoding an instruction is this same counting problem.

Remember: n bits hold 2ⁿ patterns. Unsigned runs from 0 to 2ⁿ−1. Signed runs from −2ⁿ⁻¹ to 2ⁿ⁻¹−1. The bits do not say which reading you meant.

More detail

Languages such as C have separate signed and unsigned types so the compiler picks the comparison and the extension. At the moment of the addition, the ALU only sees bits.

ASCII, used later for strings, is a 7-bit pattern inside a byte. The classic anchors are 0x30 = '0', 0x41 = 'A', 0x61 = 'a'.

Source: Lecture 5, “What does a binary number represent?”, “Unsigned and signed numbers”.

Part 2 · Numbers

Carry out is not the same as overflow

One sum, two verdicts

  11111000
+ 00001111
  --------
  00000111   and a carry out of the top bit
  • Unsigned: 248 + 15 = 263, which does not fit in a byte. The stored 7 is wrong. The carry out is the unsigned overflow flag.
  • Signed: −8 + 15 = 7. The result is right. The carry out is ignored.

The lecture’s point, with the rocket-scientist warning attached: the identical bits are a correct signed answer and a wrong unsigned answer.

Signed overflow is about the sign

  • A negative plus a positive cannot overflow. The result sits between them.
  • Negative plus negative must stay negative.
  • Positive plus positive must stay positive.
  • If the sign comes out wrong, that is signed overflow, whether or not there was a carry out.
11111110 + 11111011 = 11111001
−2 + −5 = −7
carry out, signs agree: no signed overflow

01111110 + 01111011 = 11111001
126 + 123 looks negative
no carry out, signs disagree: overflow

Remember: A carry out of the top bit means unsigned overflow. Signed overflow is two numbers of the same sign adding to the opposite sign.

More detail

MIPS splits the instructions on purpose. add and sub trap when the signed sum overflows. addu and subu perform the same bit operation and stay quiet. The “u” is about the trap, not about a different adder. Part 3 uses that.

A comparison has the same split. As unsigned, 11111000 > 00000111 (248 > 7). As signed, it is −8 > 7, which is false. slt and sltu are the two readings.

Source: Lecture 5, “Traps for the unwary”, “carry out”, “signed overflow”.

Part 2 · Numbers

Words, byte order, and widening

A word is the processor’s native size

MachineByteNext sizes
MIPS32, which this course uses8 bitshalfword 16, word 32, doubleword 64
80x868word 16, doubleword 32

Memory itself is a row of bytes, each with an address. A MIPS register holds 32 bits, so a load of a word has to gather four addresses. Addresses of words step by 4: 0, 4, 8, …

158510 = 00000110 001100012 as 16 bits (0x0631). Put it at address 6.

OrderAddress 6Address 7
Big-endian: high byte first0000011000110001
Little-endian: low byte first0011000100000110

Making a small value fill a register

Sign extension copies the top bit, for a signed value.

00001001  →  00000000 00000000 00000000 00001001     9 stays 9
11111001  →  11111111 11111111 11111111 11111001    −7 stays −7

Zero extension fills with zeros, for an unsigned value or a raw bit pattern. The byte 11111001 zero-extended is 249, not −7.

Load instructions come in pairs for this reason. A signed load sign-extends. An unsigned load zero-extends. Storing a byte writes only that byte.

Remember: Little-endian stores the low byte at the low address. Widen a signed value by copying the sign bit. Widen an unsigned value with zeros.

More detail

For a 32-bit word, little-endian puts the least significant byte at address n and the most significant byte at address n+3. Big-endian does the reverse. Get the order wrong and integers come out byte-swapped; text often still looks almost right, which makes the bug harder.

MIPS load/store pairs, used from the next part: lb/lbu and lh/lhu are the signed and unsigned loads of a byte and a halfword. sb and sh store them. lw and sw move a full word, so no extension choice arises.

Source: Lecture 5, “Byte order”, “sign extension”, “zero extension”; MIPS sizes from the same lecture.
