Part 1 · Machine

Architecture is the programmer’s view

Two words the course splits apart

A computer’s architecture is the abstract machine a programmer programs: what data it handles, where that data can sit, and which instructions can touch it. That contract is the instruction set architecture (ISA).

Organisation is one physical way of building that contract. The same ISA can be built in different hardware. x86 is one architecture, implemented differently by Intel and by AMD.

What the course is for

  • Take the mystery out of how a machine actually runs a program
  • Be able to talk about assembly, registers and memory
  • See how later modules depend on representation and execution

Assessment on the course is an in-person test (80%) and a group coursework (20%).

Remember: Architecture is the instruction set the programmer sees. Organisation is one way of building it.

More detail

The recommended books are Harris and Harris, Digital Design and Computer Architecture (binary, MIPS, assembly; full text via the library), Patterson and Hennessy, Computer Organization and Design (the MIPS book, more detailed than this course needs), and Silberschatz, Galvin and Gagne, Operating System Concepts for the second half.

Lectures 1 and 11 say the microprogramming level and the raw digital-logic level are outside this module. You are learning the ISA, assembly, and the operating system that sits on top.

Source: Lecture 1, “Computer Architecture”, “Purpose of the Course”, “Course Assessment”.

Same ideas, very different machines

A line worth knowing

MachineWhat it shows
Analytical Engine, Babbage, 1834–1871Gears holding 40-digit decimals, a store of 1,000 of them, + − × ÷, and a program on punched cards. Branching makes it general purpose.
Colossus, 1943Programmable electronic computer at Bletchley Park, binary operations in valves.
ENIAC, 1946Electronic, thermionic valves.
Intel 4004, 1971A processor on one chip.
Multicore, from the 2000sMoore’s law ran into a wall; chips grew extra cores instead of only faster clocks.

Why this course studies MIPS

The ideas are shared. Once you can follow one processor, the next one is mostly a change of names and encoding.

The Intel cores in a laptop are complicated by decades of compatibility. MIPS is a small, regular design that still shows the same mechanisms: registers, a program counter, loads and stores, branches.

The lectures also mention machines at both extremes: a supercomputer of millions of cores, and a tiny board that is still a computer.

Remember: The machines changed. The stored-program idea did not. MIPS is the clean place to learn it.

More detail

Babbage’s engine is described as Turing complete because it can branch, so the next instruction need not be the next card. You will meet that same idea as the Little Man’s BRA, and again as a MIPS branch.

A quantum computer is mentioned only as a picture of how far organisation can move while people still talk about an architecture. It is not examined as a model in these lectures.

Source: Lecture 1, “The Analytical Engine” through “Why choose a machine to study”.

What you will actually cross

The course walks level 5 down into level 4 and level 2: a high-level statement, the MIPS instruction a compiler emits, and the bits of that instruction.

Level 3 is the second half of the module. The operating system is the layer that starts the machine, runs many programs, and offers services such as “print this integer”.

Remember: One addition is the same idea at every level, from i = i + 1 down to a word of bits.

More detail

The bit pattern on the slide is the machine encoding of that assembly instruction. You will build patterns like it, field by field, in Part 3.

Abstraction, as the lecture defines it, means keeping the details that matter at this level and ignoring the machinery underneath. Each level is a model of the one below.

Part 1 · Machine

One memory holds the program and the data

The picture every later lecture redraws

CPU

Memory

Input / output

Modern machines settled on a stored-program design, the von Neumann picture. The processor, the memory, and the devices sit on buses. Memory holds both instructions and data.

The processor fetches a word, treats it as an instruction, then fetches the next one. Nothing in the word itself says “this is code”. The program counter decides.

Three buses, three jobs

BusCarries
AddressWhich location
DataThe word going in or out
Control and statusRead, write, clock, ready

An old IBM PC bus makes the widths obvious: 20 address wires can name 220 = 1 MB of locations, and 8 data wires move one byte at a time. A wire at one voltage is a 1, at the other a 0.

Remember: Instructions and data share one memory. The program counter says which word is fetched next.

More detail

The Little Man Computer, introduced next, is this diagram with the person as the processor, mailboxes as memory, and an in-basket and out-basket as the only I/O.

Lecture 3 stresses that a real motherboard has several different buses (SATA for a disk, PCI Express for a network card), while the programmer’s abstract picture collapses them into address, data, and control.

Source: Lecture 1, “stored program von Neumann architecture”; Lecture 3, “Inside the Box”.

Part 1 · Machine

The Little Man and his mailboxes

What is in the room

  • 100 mailboxes, addressed 00 to 99. Each holds one 3-digit decimal number.
  • A calculator: the accumulator. Arithmetic happens here.
  • A two-digit instruction location counter: the address of the next instruction. This is the program counter.
  • An in basket and an out basket. Three-digit numbers are the only way in or out.

A mailbox holds either a data value or an instruction. An instruction is one digit of opcode and two digits of operand.

One mailbox, two readings

399
│└┴ operand: mailbox 99
└ opcode 3: STA, store the accumulator

The Higginson simulator used in the lectures shows the same room as a CPU with a few registers: accumulator, program counter, instruction register (the opcode digit), and address register (the other two digits).

The original analogy is Stuart Madnick’s, MIT, 1965. The course follows peterhigginson.co.uk/LMC, whose opcodes differ from some textbooks.

Remember: A mailbox holds one 3-digit word: a number, or an opcode plus an address.

More detail

Decimal is a teaching choice. Lecture 3’s last point is that the Little Man’s room matches real hardware, except that real machines use binary. Part 2 is that change of base.

Because instructions and data share the mailboxes, a program can (carefully) treat one as the other. That is the stored-program idea in miniature.

Source: Lecture 2, “The Little Man Computer”, “The Mailboxes”, “CPU registers”.

The instruction set, and adding two inputs

Opcodes in this course

MnemonicCodeEffect

Add two numbers

Mailbox  Mnemonic   Code   What happens
00       INP        901    first number → accumulator
01       STA 99     399    keep it in mailbox 99
02       INP        901    second number → accumulator
03       ADD 99     199    add the saved first number
04       OUT        902    show the sum
05       HLT        000    stop

Each mnemonic translates 1-to-1 into a mailbox value. ADD 99 and 199 are the same instruction, one for you and one for the Little Man.

Remember: Assembly is a 1-to-1 renaming of machine code. ADD 99 and 199 are the same instruction.

More detail

DAT is an assembler instruction, not one the Little Man executes. DAT 5 reserves the next mailbox and puts 5 in it. DAT with no number reserves a mailbox for a variable. Labels name mailboxes so you can write ADD NUM instead of ADD 99.

Walk the add program once on paper. After mailbox 01 the first input sits in mailbox 99 and the counter is 02. After mailbox 03 the accumulator holds the sum. Mailboxes 00–05 still hold the program: storing the data at 99 is what keeps the program from being overwritten.

Source: Lecture 2, “LMC Instruction Set”, “add two numbers”, “DAT”, “Labels”.

Part 1 · Machine

A branch is what makes it a computer

Two kinds of jump

An ordinary calculator always does the next step. A branch writes a new address into the instruction location counter, so the next fetch is somewhere else.

  • BRA always jumps. The Little Man puts the operand into the counter.
  • BRZ jumps only when the accumulator is zero.
  • BRP jumps when the accumulator is positive or zero.

The counter is incremented just after it is read, before the instruction runs. A branch then overwrites that already-incremented value. If the increment happened after the instruction, it would undo the branch.

|x − y|, then a sentinel loop

00 INP        01 STA 10
02 INP        03 STA 11
04 SUB 10     05 BRP 08
06 LDA 10     07 SUB 11
08 OUT        09 HLT

After SUB 10 the accumulator holds the second input minus the first. If that is ≥ 0, BRP skips to the output. If it is negative, the next two instructions compute first minus second instead. That is an if.

START     INP
          BRZ END
          ADD SUBTOTAL
          STA SUBTOTAL
          BRA START
END       LDA SUBTOTAL
          OUT
          HLT
SUBTOTAL  DAT

A 0 input ends the loop. Anything else is added into the mailbox labelled SUBTOTAL. That is a while loop.

Remember: A branch writes a new address into the program counter. That is what makes the machine more than a calculator.

More detail

The lecture’s absolute-value fragment stores the two inputs at mailboxes 10 and 11 (codes 310 and 311) and branches with 808, which is BRP to mailbox 08. The two instructions the slide asks about, LDA then SUB, replace a negative difference with its positive counterpart.

Trace |3 − 5|. Inputs 3 then 5. Accumulator becomes 5 − 3 = 2, which is positive, so BRP goes straight to OUT and the result is 2. Trace |5 − 3| the other way round and the branch is not taken: LDA loads 5, SUB subtracts 3, OUT prints 2.

Source: Lecture 2, “Branching”, “absolute value”, “sum of a series”.

Part 1 · Machine

Fetch, decode, execute, then the real box

The Little Man’s cycle

Read the instruction location counter

Increment it, so it already points at the next instruction

Fetch the mailbox it named

Decode the opcode

Fetch the operand

Execute, and store any result

Then he does it again, until HLT. Real processors run the same fetch–decode–execute loop. The lecture’s name for the counter’s early increment is the detail that makes branches work.

What you would see if you opened the case

  • A CPU in a socket, and RAM in the slots beside it.
  • Disks and SSDs on a storage bus such as SATA. A network card on PCI Express.
  • A GPU: another processor, built for huge numbers of similar calculations (graphics, and training large models). A machine with both is a heterogeneous system.

The programmer’s diagram hides those sockets. It still shows a CPU, a memory, devices, and three buses. The Little Man is that diagram, drawn with mailboxes.

Remember: Real hardware is the Little Man’s room: a processor, a memory of instructions and data, and buses instead of a person. The numbers are binary.

More detail

Lecture 3’s summary list is processor, memory and storage, input and output, and the buses between them. The next lecture starts the binary those buses actually carry.

Primary memory is the RAM the CPU addresses directly. A magnetic disk or SSD is larger and keeps its contents with the power off; it is not on the “mailboxes the Little Man can open in one step” side of the picture. Parts 5 and 8 come back to how a program gets from the disk into RAM.

Source: Lecture 2, “Little Man Instruction Cycle”; Lecture 3, “Inside the Box”, “GPU”.
