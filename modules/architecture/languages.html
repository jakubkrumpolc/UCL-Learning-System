The registers have jobs

NameNumberJob
$zero0Constant 0
$at1Assembler temporary. Leave it alone
$v0–$v12–3Values returned from a procedure
$a0–$a34–7The first four arguments
$t0–$t78–15Temporaries. A call may destroy them
$s0–$s716–23Saved. A call must leave them as it found them
$t8–$t924–25More temporaries
$k0–$k126–27Kernel
$gp, $sp, $fp, $ra28–31Global pointer, stack pointer, frame pointer, return address

A few locals, the lecture’s way

Saved registers hold variables that have to survive. The lecture’s three integers:

# a = 64, b = 0x12345678, c = a + b
addiu $s0, $0, 0x0040
lui   $s1, 0x1234
ori   $s1, $s1, 0x5678   # or: li $s1, 0x12345678
addu  $s2, $s0, $s1

An array is a base address in a saved register, and element i of a word array is at offset 4i. Doubling array[0] and array[1] is load, shift left by 1, store, at offsets 0 and 4.

Remember: $a0–$a3 carry arguments in. $v0–$v1 carry results out. $t registers are scratch. $s registers survive a call.

More detail

The lecture also says $gp, $sp, $fp and $ra must be saved and restored if a procedure changes them. $gp is normally left at 0x10008000, pointing into the static data. You will move $sp and save $ra in the stack section.

Using the numbered names ($8) and the conventional names ($t0) is the same register. The names are there so the contract is visible. $t0 is $8. $s0 is $16. $ra is $31.

Source: Lecture 9, “Register usage convention”, the a/b/c example and the array example.

if, while and for

if / else, branched the short way

# $s0=f, $s1=g, $s2=h, $s3=i, $s4=j
# if (i == j) f = g + h; else f = f - i;
      bne  $s3, $s4, L1
      addu $s0, $s1, $s2
      j    done
L1:   subu $s0, $s0, $s3
done:

The branch skips the then-arm. The jump skips the else-arm. One of the two assignments runs.

A while, and a for that adds 0 through 9

# while pow != 128: pow *= 2; x++
      addiu $s0, $0, 1      # pow
      addu  $s1, $0, $0      # x
      addiu $t0, $0, 128
while:beq  $s0, $t0, done
      sll   $s0, $s0, 1
      addiu $s1, $s1, 1
      j     while
done:
# for (i = 0; i != 10; i++) sum += i
      addiu $s1, $0, 0
      addu  $s0, $0, $0
      addiu $t0, $0, 10
for:  beq   $s0, $t0, done
      addu  $s1, $s1, $s0
      addiu $s0, $s0, 1
      j     for
done:

The test sits at the top. The jump at the bottom closes the loop. Multiplying by two is a left shift, not a multiply instruction.

Remember: An if is a branch around one arm and a jump around the other. A loop tests at the top, and jumps back from the bottom.

More detail

Write the condition the way the branch can ask it. “Leave the loop when pow hits 128” becomes beq against a register holding 128. “Stay in the for while i differs from 10” is the same shape.

The sum program finishes with $s1 = 0+1+…+9 = 45 and $s0 = 10. Step it for the first two iterations only: after them, sum is 1 and i is 2. If that is right, the shape is right.

Source: Lecture 9, “If … else”, “While loops”, “For loops”.

jal saves the way home

Three jump instructions

InstructionEffect
j targetPC’s low 28 bits ← target × 4. A goto.
jal target$ra ← PC+4, then jump. A call.
jr $raPC ← $ra. A return.

J-type holds a 26-bit target. Addresses are multiples of four, so those 26 bits become 28 bits of byte address, and the top 4 bits of the PC stay put. jr is the exception: the whole 32-bit address comes from a register.

0x0041AB38   jal procedure
0x0041AB3C   ... comes back here, because $ra was set to this address

procedure:
              ...
              jr $ra

abs as a procedure

abs_proc:
      sub  $v0, $a0, $a1   # result = a - b
      bgez $v0, return
      sub  $v0, $a1, $a0   # result = b - a
return:
      jr   $ra

The caller puts the two numbers in $a0 and $a1, executes jal abs_proc, and reads the answer from $v0. The procedure does not need to know who called it. That is the point of the convention.

It is also where a nested call breaks. jal abs_proc overwrites $ra. If the caller still needs its own return address, that address is gone, and jr $ra comes back to the wrong place, often as an infinite loop.

Remember: jal writes the next address into $ra and jumps. jr $ra returns. A nested jal overwrites $ra unless you have saved it.

More detail

The lecture’s version 2 calls my_program from main, and my_program calls abs_proc. The inner jal destroys the $ra that my_program needed. The next section is the repair, and it is the stack.

j is not a call. It does not touch $ra. Use it for the “skip the else” and “go back to the top of the loop” jumps in the previous section. Use jal only when something must return.

Source: Lecture 9, “J-format”, “jal and jr”, “abs_proc”, “the $ra problem”.

Who is allowed to smash which register

Caller and callee

A procedure must be usable from anywhere, including from another procedure, without a private arrangement about registers.

  • Temporary ($t) registers are free for the callee to overwrite. If the caller still wants a value, the caller saves it before the jal.
  • Saved ($s) registers survive. If the callee wants one, the callee saves it and restores it before returning.
  • $ra is saved, because the callee may itself call someone.

Either side can do the saving. The convention says which side, so both do not, and neither forgets.

Four arguments, then the stack

Arguments beyond the fourth do not get a register. They go on the stack, which is also where saved registers go. The stack is the only place that still works when calls nest: each call pushes its own copy, and a later call cannot overwrite an earlier call’s slot.

Return values use $v0 and, if there are two of them or the value is 64 bits wide, $v1. The caller knows to look there, so the callee does not also store the result to a private memory cell.

Remember: The caller may trust $s registers and must assume $t registers die. A procedure that uses an $s register, or that calls onward, saves and restores what it will overwrite.

More detail

The lecture’s table is worth memorising as two columns: “preserved across a call?” Yes for $s0–$s7, and for $gp, $sp, $fp, $ra if they change. No for $t0–$t9.

$at is reserved for the assembler when it expands a pseudo-instruction such as la into two real instructions. Writing it yourself races the assembler.

Source: Lecture 9, “preserved across a call”, “problems when one procedure calls another”.

The frame the lecture actually builds

Push, then pop

The stack grows downward. $sp points at the top, which is the lowest address in use. Making an 8-byte frame subtracts 8.

addi $sp, $sp, -8    # two words of room
sw   $ra, 4($sp)     # saved return address
sw   $fp, 0($sp)     # saved frame pointer
addi $fp, $sp, 4     # this frame’s fp

The procedure then does its work, including the inner jal. Coming back, it reverses the stores before it touches $sp, so the loads still see the right addresses.

lw   $ra, 4($sp)
lw   $fp, 0($sp)
addi $sp, $sp, 8
jr   $ra

Why both pointers

$fp, once set, stays put while the procedure runs, even if a later push moves $sp. Locals can be named as fixed offsets from $fp. $sp moves; $fp anchors the frame.

In the lecture’s repaired program, my_program saves $ra and $fp, loads A and B from memory into $a0 and $a1, calls abs_proc, stores $v0 back to memory, restores the two registers, and only then returns. The inner call is now safe, because the outer return address spent the call sitting on the stack rather than in $ra.

Picture, from the top of the frame downward: saved $ra, saved $fp, then any callee data. The new $fp points at the saved $ra.

Remember: The stack grows down. Subtract from $sp, store $ra and $fp, do the work, load them back, add the same amount to $sp, then jr $ra.

More detail

Order matters on the way out. Restoring $fp from 0($sp) and then adding 8 to $sp is correct. Adding to $sp first would load from the wrong place. The lecture’s listing restores, then adjusts $sp, then returns.

Eight bytes is this frame, because two registers are saved. A procedure that also saves $s0 would subtract 12 (or 16, to keep the stack aligned) and store $s0 in the extra slot. The shape does not change.

Source: Lecture 9, “Pushing” and “Popping”, and the repaired absolute-difference program.

Asking MARS to read and print

The services the lecture lists

$v0ServiceArgument or result
1print_int$a0 = the integer
2print_float$f12 = the float
4print_string$a0 = address of the string
5read_intresult comes back in $v0
8read_string$a0 = buffer, $a1 = length
10exitno argument
12read_charresult in $v0

Put the number in $v0, put any argument in the register the table names, then execute syscall. A result comes back in the register the table names, often $v0, so copy it aside before the next call reuses $v0.

Add two typed integers

.data
str1: .asciiz "Enter first value: "
str3: .asciiz "Sum is equal to "
.text
addi $v0, $0, 4
la   $a0, str1
syscall            # print the prompt
addi $v0, $0, 5
syscall            # read into $v0
add  $t1, $0, $v0  # keep it, $v0 is about to be reused

The lecture’s program prints a second prompt, reads again, adds into $t1, prints “Sum is equal to ”, then print_int with the sum in $a0. Code 4, then 5, then 4, then 1. Exit, when you want it, is code 10.

This is a different kind of call from jal. syscall crosses into the operating system. The number in $v0 chooses the service. The same idea, with different numbers, is how a real kernel is asked for a file or a process.

Remember: Put a service number in $v0, arguments in the documented registers, and execute syscall. 4 prints a string, 5 reads an int, 1 prints an int, 10 exits.

More detail

Copy a returned integer out of $v0 immediately. The next addi $v0, $0, 4 overwrites it. The lecture uses $t1, which is a reasonable scratch register because this fragment does not call an ordinary procedure in between.

Strings for these calls are .asciiz, so they already end in a zero byte. print_string walks memory until that zero. Forget it, and the print runs on into whatever bytes follow.

Source: Lecture 9, the MARS syscall table and the interactive calculator (version 3).

Characters, strings, and a fixed binary point

ASCII, then a C string

The anchors: '0' is 0x30, 'A' is 0x41, 'a' is 0x61. Digits are contiguous, so the numeric value of a digit character is the byte minus 0x30. Control bytes the lecture names: tab 0x09, line feed 0x0A, carriage return 0x0D, escape 0x1B, backspace 0x08.

A C string, which is what MIPS .asciiz builds, is those bytes one after another, then a 0x00. Python’s str is a more complicated Unicode object. At this level you are looking at the C representation.

“Hello” in memory is the bytes 48 65 6C 6C 6F, and an asciiz directive writes a 00 after them.

Fixed point keeps the point in your head

A real number can be a power series that continues to the right of the point. 2−1 = 0.5, 2−2 = 0.25, 2−3 = 0.125. So 11.1012 = 2 + 1 + 0.5 + 0.125 = 3.62510, and 5.7510 = 101.112.

Fixed point stores that pattern in an integer register and does not record where the point is. With 4 fraction bits, 1.12 is stored as the integer 0001 1000. Addition just works. A product has twice as many fraction bits, so you shift the integer product right by 4 to put the point back.

Negating a fixed-point value is still “flip the bits and add 1”, and the +1 goes into the least significant fraction bit, not into the units bit.

Remember: A C string is ASCII bytes ending in 0. A fixed-point binary point is a convention, not a stored bit. After a fixed-point multiply, shift right by the number of fraction bits.

More detail

Converting a fraction: multiply by 2 and record the integer part, then repeat on what is left. 0.75 × 2 = 1.5, record 1; 0.5 × 2 = 1.0, record 1. So 0.7510 = 0.112, and with the integer 5 that is 101.112.

The lecture’s 12-bit example with the point between bits 3 and 4 adds 1.1 and 1.0 to get 2.5 by ordinary integer addition. The multiply produces four extra low zeros of fraction, and a right shift of 4 removes them.

Source: Lecture 10, ASCII, strings, fixed-point representation and the multiply example.

IEEE 754, and the floating-point calculator

One sign, a biased exponent, a hidden 1

Single precision is 32 bits, the C and Java float. The value is (−1)S × 1.F × 2E − 127, for a normal number.

FieldBitsRole
S10 positive, 1 negative
E8exponent plus the bias 127
F23the fraction to the right of the leading 1, which is not stored
−12.75 = −1100.11₂ = −1.10011₂ × 2³
E = 3 + 127 = 130 = 10000010₂
S = 1,  F = 10011000…0

1 10000010 10011000000000000000000
= C14C0000₁₆

1.0 is the useful check: S = 0, E = 127, F = 0, so the word is 0x3F800000.

Specials, then the coprocessor

PatternMeaning
E = 0, F = 0+0 or −0, from the sign
E = 0, F ≠ 0denormal: 0.F × 2−126, the gap between 0 and the smallest normal
E = 255, F = 0+∞ or −∞
E = 255, F ≠ 0NaN, from 0/0 or √(negative). An operation with NaN gives NaN

The smallest positive normal is 1.0 × 2−126. The largest is just under 2128. MIPS does this arithmetic on coprocessor 1, in $f0–$f31.

.data
vals: .float 3.14, 10.0, 0.0
.text
la    $4, vals
lwc1  $f0, 0($4)
lwc1  $f1, 4($4)
mul.s $f2, $f0, $f1
swc1  $f2, 8($4)

add.s, sub.s, mul.s, div.s are single. The .d forms are double, which occupies an even-odd pair of $f registers and is only addressed by the even one.

Remember: A normal float is (−1)ˢ × 1.F × 2ᴱ⁻¹²⁷. E = 0 and E = 255 are reserved: zero, denormals, infinity, NaN. −12.75 is 0xC14C0000.

More detail

The leading 1 is free accuracy: every normal number is shifted until it starts with 1, so that bit need not be stored. Denormals drop the assumption, which is why their formula is 0.F × 21−bias rather than 1.F × 2E−bias.

Double precision is the same idea with more exponent bits and more fraction bits. The lecture works the single format in detail and says the double format is the same shape. lwc1 and swc1 move one float between memory and the coprocessor; integer lw cannot feed mul.s.

Source: Lecture 10, IEEE single precision, the −12.75 encoding, specials, and the floating-point calculator.
